# Twine: notes for working on it

The app is called **Twine** (first called eMotion; renamed on 27 September 2026, and on 28 September 2026 the user asked for the old name to go everywhere). Everything says Twine: the repo folder `Documents/Claude Code/Twine`, the source folder `Twine/`, `Twine.xcodeproj` and its target and scheme, the bundle id `com.nidhin.twine` (test copy `com.nidhin.twine.selftest`, `build/TwineTest.app`), the pasteboard types, the `TWINE_` environment variables and `~/Documents/Twine Creations`. Projects end in `.twine` (`com.nidhin.twine.project`); the old `.emotion` type is no longer declared or read, as none were left. `App/FormerName.swift` is the only code with the old name: on the first launch as Twine it moves `~/Documents/eMotion Creations` to `Twine Creations` and copies the `com.nidhin.emotion` settings domain across (each only when the old exists and the new does not; never in the test copy). The version history keeps its two entries about the first rename as they were. The GitHub repo is `inbox-nidhinm/Twine`.

The original brief is `docs/brief.md`. The project is now working through a Jitter-style redesign: `docs/redesign.md` (the brief) and `docs/redesign-decisions.md` (answers, which win where they differ). Read both before a milestone. This file is the map and the rules.

## Rules

- **No em dashes anywhere**: UI strings, comments, docs, commit messages.
- No third-party dependencies without asking.
- Every milestone ends with: `./make-app.sh` with no warnings, `./test.sh` passing, the change written into the top build of `Twine/VersionHistory.swift` (see below), a commit, and a push to `inbox-nidhinm/Twine`.
- **Builds are releases, not changes** (30 September 2026, the user's request): `VersionHistory.builds` has about a dozen entries, each with `features`, `fixes` and `misc` lists (shown as Feature updates, Bug fixes and Misc, an empty list left out). Write each change as a line in the top build's list that fits it; start a new build (which raises the version number) only when the user says to cut one. Fold a change that undoes an earlier one in the same build into the final state. `VersionHistory.pushes` counts pushes to GitHub, the first being v0.0.01 and the 100th v0.1.00 (`release`, shown small beside the card's title): raise it by one in every commit you push. The build numbers in these notes ("build 43") are the old numbering, one per change, from before this.
- The user is a designer, not an engineer. Explain in plain terms.
- No help text in the UI. States are shown, not explained. Put explanations in `.help()` tooltips.
- Views never write literals: every colour, size and radius comes from `Theme` (in `Packages/MotionKit/Sources/Theme`). Values come from the "Flip Design System" page of Figma file `2XErpBfGuIGNU0DkL58Ute` (node 171:2055), with a blue accent (#217FD8, #4C9FEF until 2 October 2026) in place of Flip's green.
- **Accessibility presses do not prove clicks work.** They skip hit testing. To test real clicks without touching the user's mouse, post `NSEvent` mouse and key events through `window.sendEvent` from a temporary in-app hook, and log state after each. After each step post an `.applicationDefined` event through `NSApp.postEvent`: events sent straight to a window skip the event loop, so the undo group never closes, the document never counts as edited, and nothing saves. Remove the hook before committing.
- **Posted events do not reliably reach SwiftUI gestures.** `onTapGesture` and `DragGesture` sometimes ignore events sent through `window.sendEvent` for a whole session, while real `Button`s always respond. Make clickable controls real buttons; for drags in SwiftUI views (the curve editor), set the value from the hook and say the drag itself was not exercised.
- **The save panel runs in another process.** A test hook can fill it in (`directoryURL` is ignored once it is up; set `NSNavLastRootDirectory` in the test copy's defaults instead) and close it with `window.endSheet(panel, returnCode: .OK)`; `panel.ok(nil)` throws. Errors are presented as sheets on the window (`presentError(_:modalFor:...)`) so they show in window captures.
- **`hitTest` takes a point in the view's superview's coordinates.** For the window's content view that is the frame view, which runs upward, while the content view runs downward, so `content.hitTest(content.convert(p, from: nil))` mirrors the point top to bottom. Use `ChromelessWindow.viewUnder(_:)`. A test hook that builds its points the same wrong way passes anyway: that is how canvas hover shipped broken over the top of the canvas in Animate.
- **A test copy's documents can become the user's work.** On 28 September 2026 the user kept working in a TwineTest window the kit had opened, and the next run wiped that project copy. `run.sh` now puts each run's copy in the run's own folder, moves an earlier run of the same name to the Bin, and asks TwineTest to quit (so it saves) before forcing it. Before a run, check whether TwineTest is open and whether its projects changed after the last run; if so, ask the user.
- **Never drive the copy of the app the user is using.** For scripted tests make a copy of `build/Twine.app` with its own bundle id (`com.nidhin.twine.selftest`) and point it at a throwaway project in the scratchpad.
- When driving the running app to verify, the user is often working in other apps. Launch with `open -g`, use accessibility presses (`click button N of ...`) rather than synthetic keys or clicks, and never type unless Twine is frontmost. Setting a SwiftUI text field's value through accessibility does not reach its binding.

## Signing

Ad-hoc signed (`CODE_SIGN_IDENTITY = "-"`), no App Sandbox (ffmpeg and any chosen folder need it off), and the Hardened Runtime on in both configurations (4 October 2026, after the security review): nothing outside can inject code into Twine or attach a debugger to it, and it needs no exceptions (the private Core Animation classes, the cursor swap and launching ffmpeg all work under it). Release leaves out Xcode's `get-task-allow` (`CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO`). Debug builds one program (`ENABLE_DEBUG_DYLIB = NO`): the runtime refuses to load Xcode's separate ad-hoc-signed `Twine.debug.dylib` ("different Team IDs"), so the test copy would not start. The test copy is re-signed with the runtime and `Tools/SelfTest/TwineTest.entitlements` (`get-task-allow` only), so `sample` and `profile.sh` can read it.

## Testing in the app

`Tools/SelfTest/` holds the kit: install the driver with `install-hook.sh`, build the separate test copy with `make-test-app.sh`, drive it with `run.sh PROJECT NAME "steps"`, profile with `profile.sh`, and always `remove-hook.sh` before committing (`Twine/App/SelfTest.swift` is git-ignored as a guard). The driver is compiled only into the test copy: `make-test-app.sh` builds with `TWINE_SELFTEST_BUILD=1`, which `make-app.sh` turns into `-D SELFTEST`, and `SelfTest.swift` is an empty `run` without it; any other `make-app.sh` refuses while the hook is installed (4 October 2026), so remove it before the release rebuild. Its README lists every step and the ways a test can fool you. `make-test-app.sh` runs `make-app.sh`, so it replaces `build/Twine.app`, which the user may have open: say so first, and rebuild release before finishing. Unit tests stay in the packages (`./test.sh`); the kit is for what only the running app shows.

## Decisions worth knowing

- **Undo is by snapshot.** `ProjectStore` records the whole `Project` before each command. Drags and sliders use `beginContinuousChange` / `updateContinuousChange` / `endContinuousChange` so they undo as one step. History is capped (28 September 2026): at most `ProjectStore.undoSteps` (200) steps, and about `undoBudget` (512 MB) of snapshots, each step's cost estimated when recorded (`cost(of:against:)`: the layer and action lists it copied; paths and words inside layers are not counted); past the budget the oldest steps go, by lowering the undo manager's `levelsOfUndo` for a moment. `undoCosts`/`redoCosts` follow undo and redo. `perform(_:joining:)` adds to the last step when it came from there with the same key and nothing has happened since (any other step, undo, redo or a continuous change clears `joinable`): typing uses it, so a change made between letters is its own step in order, rather than one change held open swallowing it.
- **Layers are stored back to front** (last in the array is in front). The layers panel shows them reversed.
- **Coordinates are Figma's**: origin top-left, y down, rotation clockwise in degrees (Figma's own rotation is counter-clockwise: an importer negates it). Anchor is in pixels from the layer's top-left. Scale 1 is 100%, opacity 0 to 1.
- **Skew and tilt** (28 September 2026): `Transform.skew` (degrees each way: x slants the sides, the bottom moving right; y the top and bottom) and `Transform.tilt` (`Tilt`: x tips around a level line through the anchor, top away; y turns around an upright one, right side away; `depth` is the viewing distance, 1200 by default), both left out of files when zero. A layer's flat transform is `Affine.layer(... skew:)` (scale, skew, rotation about the anchor), and every place that rebuilds one passes the skew, so resizing, anchors and grouping stay exact for skewed layers (ungrouping a skewed group loses its skew, as it loses an uneven stretch). A tilt is not flat: `Projective` (a 3 by 3 perspective matrix, exact for a flat layer turned in depth, which `caTransform` hands to Core Animation, so canvas, exports and thumbnails match; `WarpRenderingTests` checks pixels) with `Projective.layer` tilting after rotation. `ResolvedLayer.transform` stays flat (editing works in it); `.projection` and `ResolvedScene.worldProjection` are as drawn, and `worldCorners` (outlines, bounds, snapping), hit testing, clipping checks and `ResolvedMask.transform` follow them. A tilted layer, or anything in a tilted group, shows its outline but no handles (`CanvasNSView.isTilted`), since the handles' maths are flat; it is sized in the inspector. Dragging layers inside a tilted group is flat, so a little off. `Warp` boxes skew and tilt in `LayerState` and `ResolvedLayer` (an `indirect` case, `.none` for straight layers), as picture paints are, to keep states small. Skew and Tilt actions (`SkewAction`, `TiltAction`, To or By, the `skew` and `tilt` channels; By adds a tilt's angles and takes its depth) are offered wherever Move is. In the inspector they are Skew and Tilt entries in the Effects section (added from its + menu, shown while set; removing one zeroes it), Tilt with Depth once tilted.
- **Actions, not keyframes.** A layer's properties are plain values: its design state. `Project.actions` is a flat list; each `Action` targets one layer, has a start, a duration (0 is instant), an easing, and an `ActionSpec` carrying its own typed optional initial value and end value. Layers have no in or out points.
- **The action rules live in one place**: `walk` in `MotionEvaluation/ActionTracks.swift`, with its numbered comment. Each action drives one channel (position, scale, rotation, opacity, size, visibility). On one channel of one layer, actions go in start order (ties by `rowOrder`); an empty initial value inherits the value at the action's start; the first action's explicit initial value holds from time 0 (entrances); a later action takes over from the value at its own start. Channels never interfere. By mode adds (Scale By multiplies); To is absolute. Resize grows around the anchor. A layer is shown until something hides it: a Show never hides what comes before it (the user's choice on 28 September 2026; it used to hide the layer until it when it was the first). Show and Hide are kept whatever else the layer does (rule 10, the user's choice on 28 September 2026, as in Jitter): a Show or Hide at or before a channel's first action stops that action's starting value holding from 0 s, so a layer shown at 1 s with a Fade In at 3 s shows as designed until 3 s; a Show brings back a layer faded right out (opacity only, to its design; `withShows`, a `revive` step), letters faded out by a text preset too; an In preset (`PresetKind.entering`, now in MotionModel) counts as a Show on the visibility track of a layer that has a Show or Hide, so one after a Hide plays.
- **Easing** is a named preset with an intensity or a custom bezier. The presets are Jitter's (28 September 2026): Smooth, Natural, Slow down, Accelerate, Elastic (stored as `spring`), Bounce, Overshoot, Impulse, Swing and Linear (stored as `none`), plus the user's Ease out back (0.45, 1.45, 0.8, 1) and Ease in back (0.3, -0.05, 0.7, -0.5), added 4 October 2026: beziers that leave 0...1, so past the standard intensity they stray further from the line, as the lists do, rather than being applied twice (which would clip them). Presets are worked out at evaluation, so improving one improves every action. At the standard intensity (0.5) each is exactly the designer's curve: the four beziers in `designCurve`, the rest CSS `linear()` lists of 101 points in `EasingTables` (MotionEvaluation). Lower intensity fades a preset towards a straight line (a bezier by drawing its handles in); higher strengthens it (a bezier towards itself applied twice, a list by doubling how far it strays from the line, Bounce by deepening its bounces after it first lands). `Spring` is no longer used by a preset.
- **Actions follow their layers**: `EditorCommand.apply` drops actions whose layer is gone, whatever command removed it. A copy is the layer whole under a new id (`Layer.withID`; copying field by field once lost blend modes and the proportions link), with new ids for its fills, strokes and effects. A mask copies as a mask. Carrying a layer through a flipped group (a negative scale, `Arrangement.mirrors`) turns its rotation and skew the other way, and its actions' (`remapped(mirrored:)`). Times are held to `Composition.longest` (a day) by the commands and the Duration field, and frame numbers are made whole through `FrameRate.whole`, so no typed time can crash; a damaged file's frame rate of 0 reads as 30. Grouping and ungrouping remap To values and initial values into the new parent space (`Action.remapped`); duplicating and pasting copy actions through `duplicated(recordingIDs:)` and `actionCopies(for:)`.
- **File format 2** is the first with actions. Anything older is refused with a plain message (`ProjectFileError.olderVersion`, whose `failureReason` is what the open alert shows). **Format 4** (4 October 2026) added angular gradients and changes nothing older; **format 5** (the same day) made masks Figma's, older masks read into `Layer.legacyMask` and converted as the project opens. **Format 3** made pictures fills: `PictureMigration` (in `FileFormat.swift`, on the raw JSON) turns each old picture layer into a rectangle with an image fill, keeping its id, so actions and masks carry on; one stretched out of its picture's shape becomes a Crop of the whole box, so it looks the same. Opening an old file does not rewrite it until it is edited.
- **Files from anyone** (4 October 2026, after a security review): `ProjectFormat.decode`, which the editor, `Creations.read` and the Info card share, brings every JSON number past `FileSafety.limit` (1e9) back to it before anything reads the file (`FileSafety.numbersHeld`, a byte scan that copies nothing when all is in range, about 8 ms of the 84 ms the 9 MB large project takes to decode), then `Project.heldInRange()` clamps the composition (1 to 16,384 px, at most `longest`), action times and motion blur, media lengths, type sizes (`FileSafety.fontSizes`) and polygon and star corners (`FileSafety.corners`, 3 to 60, which `ShapePaths` applies too), and gives a media asset whose `fileName` is not plain (`FileSafety.isPlainName`: no path, not hidden) its own id as a name, so it shows grey. Every read of a package's file goes through `ProjectDocument.packageFile`, which refuses names that are not plain and anything not an ordinary file (a link could lead anywhere); `read(from:)` drops such entries from the media folder so no save carries them on. Where a number becomes a count or a picture's pixels, use `Int(saturating:)`: `Int(_:)` on a Double past `Int.max` stops the app (a Volume fade a billion years long did, on open). `HugeValueTests` and `FileSafetyTests` cover it. Figma pastes (`FigmaImport.read`) and Twine's own clipboards (`LayerClipboard.read`, `ActionClipboard.read`) go through `numbersHeld` and `FileSafety.held` too, and pictures inside an SVG or a paste must pass `FileSafety.pictureFits` (16,384 a side, 100 million pixels). For SVGs (4 October 2026): `SVGImport.utf8` turns UTF-16 and UTF-32 into UTF-8 before the byte checks and refuses any other encoding that does not write letters as themselves (a UTF-16 file's entities slipped past `declaresRiskyEntities`); `pictureSVG` hands the system only the definitions a picture refers to (`references(in:)`, followed through), counts what it draws with every `use` expanded (`expandedSize`) against `maxElements`, and an `SVGImport.Budget` (shared by every SVG in one Figma paste) holds all pictures to `maxPictureWork` elements and `maxPicturePixels` (4 billion, about ten seconds in release), past which the file or paste is `tooComplex`; files over `largestFile` are not read. `HostileImportTests` covers it. `SVGPictures.draw` draws one picture at a time (a lock): the system's SVG drawing asks the font service for each text's font, and the test suite's parallel SVG tests asking at once left every thread waiting on it for good, three times on 4 October 2026. Picture files (4 October 2026): `MediaLibrary.loadImage` reads one past `pictureFits` shrunk to fit as it reads (`FileSafety.pictureDrawingScale`, through ImageIO's thumbnail, which does not hold the whole picture: a 900-megapixel PNG took 4 s and 1.5 GB), and does not read one past `pictureFileFits` (400 million pixels, 65,535 a side) at all; imports refuse those with a notice (`MediaImport.isOversizedPicture`, `oversizedNotice`). `LargePictureTests` covers it. WebM files must start with Matroska's header and are read by ffmpeg and ffprobe with `-f matroska -protocol_whitelist file` (`WebMConversion.readAsWebM`): left to judge by content, ffmpeg read a `.webm` that was an ffconcat list as the files it named.
- **Frames** are groups with a look: `GroupContent.frame` (`FrameStyle`: fills, strokes, corner radii; nil for a plain group), so everything groups do (nesting, grouping, ungrouping, carrying actions) holds. `Layer.isFrame`; `Layer.look` is the fills, strokes and outline of a shape, or of a frame as a rectangle, and is what the inspector's Fill and Stroke sections, `LayerState(design:)`, pictures and cropping read and write. `evaluate` resolves a frame's look into `ResolvedLayer.frame`; `ResolvedScene.bounds(of:)` is a frame's own box. The renderer's `Node` keeps a group's children in `children`, a holder inside the container, clipped there (to the box for a group, to the frame's outline by `clipMask`), so a clipping group keeps its shadow; a frame's container holds its fills, then the holder, then its strokes (`updateShape(around:)`). Frames resize (`CanvasGeometry.resized`), are hit on their own fill and stroke, and take Resize, Colour, Stroke, Corner Radius and the blurs (`ActionFactory`); hit testing honours any clipping parent (`shows`). `LayerFactory.frame` is Figma's default (white, clipping). The Frame tool (`Tool.frame`, F, `Tool.draws`) draws one, and at mouse up takes in the siblings wholly inside it (`Arrangement.enclosed`, `adopt`); anything drawn with a press inside a frame goes into the innermost one (`CanvasNSView.frame(under:)`, `Arrangement.placed`), text too. `Arrangement.group(asFrame:)` is Frame Selection (⌥⌘G). Grouping moves layers in with `.moveLayers` rather than deleting and reinserting them. `Arrangement.move` (the layers panel's drops) keeps layers in place on screen across parents, carrying their actions.
- **Blend modes and shadows**: `Layer.blendMode` (Figma's list, `BlendMode.groups` for the menu; left out of the file at Normal) is the container's `compositingFilter` from `Blending` (Core Animation's private filters by name; all 17 match the W3C formulas Figma uses to within 3% in `BlendRenderingTests`, except Soft Light, Pegtop's formula, up to 5% darker in dark colours; Core Image's was further off). A group at Normal passes its children's blending through, as Figma's Pass Through. The composition's background is the renderer's `contentLayer`'s own colour, under the layers: a blend only sees what is drawn in its own superlayer, and while the background was a layer beside them (until 29 September 2026) every mode drew as Normal over it (`blendModesBlendWithTheBackground`). A mask's own node ignores blend (`ignoresBlend`). `EffectKind.innerShadow` (shapes and frames). `ResolvedLayer.shadows` lists every drop shadow on, the first carrying the Shadow action (`state.shadow`); `innerShadows` likewise, the first carrying the Inner Shadow action (4 October 2026: `ActionSpec.innerShadow`, a `ShadowAction`, the `innerShadow` channel, `LayerState.innerShadow` boxed as `InnerShadow` since most layers have none; from nothing when the design has none, shapes and frames only). A shape or frame that draws casts all its shadows from its outline (fills and strokes as regions, `Node.outline`, cached by look), each a `ShadowLayer` drawing only its shadow with the outline knocked out, at the fills' strength (`Node.strength`: a 25% card casts a 25% shadow), as Figma does; text, video, plain groups and frames that draw nothing keep one shadow on the container, from what they draw. An `InnerShadowLayer` is a sheet with the outline (shrunk by spread) cut out, casting inward, masked to the outline, over the fills. `Node.arrange` stacks a shape's or frame's sublayers (shadows, backdrop, fills, inner shadows, a frame's children, strokes), rebuilding only when their counts change.
- **The Figma plugin** (`FigmaPlugin/`, its README says how it is added and built): `code.js` describes the selection as a `twine.figma` payload (JSON on the clipboard, copied by the panel through a hidden text box), each layer with its absolute transform so Figma's groups need no care, and flattens what Twine cannot hold while Figma can still draw it: `picture` (PNG at 2×, placed at its render bounds) for mixed-style, italic, decorated or list text, diamond gradients, picture filters or odd turns (angular gradients come in as Twine's since 4 October 2026, turned the other way round when Figma's transform mirrors them), luminance masks and unknown types; `svg` (Figma's SVG, read by `SVGImport` into a group) for vectors with painted regions or mixed winding, smoothed rectangles and rounded polygons. Frames are never flattened (their children would be); a paint they cannot keep and uneven borders are left out with a `warnings` line. A layer keeps one picture fill, the topmost shown (`keptPaints` in the plugin, so the others are not copied, and `FigmaImport.fills`): pictures stacked under it cannot be seen. A frame's picture background comes in as its own `Background` picture layer at the bottom of the frame, its size and corners, with any fills Figma drew over it (`FigmaImport.background`), so it shows in the layers panel; the fills under it stay the frame's. `FigmaImport` (MotionImport) builds the layers: transforms into each parent's space (Figma's turn is anticlockwise, so the matrix's own `atan2(b, a)` is Twine's; `place` splits any matrix into Twine's turn, skew across and scale, so skewed layers, frames and text come in as themselves since 28 September 2026, and the plugin no longer flattens them), masks as they are (Figma's and Twine's are the same), gradients and picture crops through the inverse of Figma's transforms, font style names to weights, fonts this Mac lacks noted. `EditorController.pasteFromFigma` (from Paste when the clipboard string is a payload): it is centred at its exact size, never shrunk, and the composition is never resized to fit it, even when empty (both the user's choice; the empty-project resize went on 28 September 2026); pictures are staged and reused by hash; one undo step; missing fonts and warnings go to `EditorModel.showNotice` (`NoticeCard`, six seconds). The notice is a `Notice` (text and a state: a note, work under way with an optional fraction, or done). Imports follow their work through it (the user's request, 30 September 2026): `beginWork(_:after:)` (0.4 s, so quick imports show nothing; at once for a WebM) shows a `Loader` ring, `updateWork` sets the text and how far (a WebM's conversion from ffmpeg's `-progress` lines, `out_time_us` against the probed duration), `finishWork(done:)` shows a check and the done text for three seconds, or with nil clears it; `showNotice` drops any work so an error is never written over, and the close button (`dismissNotice`) hides the work's notice for good. `FigmaPlugin/test/run.js` runs `code.js` on a stand-in for Figma and writes `test/sample-payload.json`, which `FigmaPluginSampleTests` reads. The panel is drawn as the app's panels are (28 September 2026; the design is on Page 3, "Twine plugin states", of Figma file `RRnath7INm7WH7CGLOfLdH`): a floating panel on the canvas colour with no header (Figma's window title says Twine), a preview well showing the selection as Figma draws it (`sendPreview`: each selected layer exported as PNG and laid out where it sits, newest selection wins), its name with its size and layer count, and the blue Copy button; copying shows a PP Kyoto percentage and a progress bar, and a copy a check in the well's top-right corner. `ui.src.html` is built into `ui.html` by `build.py`. Figma's manifest has no icon field, so a development plugin shows Figma's own icon; `FigmaPlugin/icon.png` (the app icon at 128) is for the publish dialog, the only place an icon is set. Figma reads a development plugin's files from its folder on every run; moving the folder means importing the manifest again (the rename to Twine did). Not yet run inside Figma.
- **SVG import** (`MotionImport`, tested in `MotionImportTests`, including a pixel comparison of Twine's drawing against the system's): the file is read with `XMLDocument` and walked with each element's full transform, so every layer is made in the SVG's own space, scaled to its final size (fitted to the composition), and the file comes in as a frame (no fill, clipping, as a viewport does) named after it. Rectangles and ellipses whose transform only moves, turns and scales keep their kind; everything else becomes a path drawn through its transform (`SVGPathData`: every command, quadratics raised, arcs cut into quarter-turn cubics). Styles follow SVG's order (attributes, `.class` rules from `<style>`, `style`), inheriting what inherits. Gradients (either units, `href` chains, `gradientTransform`) are mapped into the layer's box; `fill-rule` becomes `ShapeContent.fillRule` (even-odd is drawn with the rule and normalised into a plain area, `ResolvedShape.area`, wherever paths are cut or joined); groups of one with nothing of their own flatten. `clip-path` and alpha (or white luminance) masks become a mask layer in a Mask group with the masked one; both at once, or a mask Twine cannot draw, and the element becomes a picture. Figma's filters are read by their result names (`SVGFilters`) into drop and inner shadows and layer blur; its background blur comes from the `foreignObject` before the shape. Figma's picture fills (a `pattern` of one `use` of an embedded `image`) become picture fills with the crop; plain `<image>`s become picture rectangles. Text is drawn by `SVGPictures` (AppKit's own SVG drawing, which draws no filters, misplaces positioned `tspan`s, so each becomes a `<text>`, and reads font weights only as numbers) from an SVG of just that element inside its ancestors' styles, with every definition, trimmed to its ink and placed there as a picture. `Result.reusing` swaps in pictures the project has. `EditorController.importSVG` stages the pictures (`ProjectDocument.stage(_ data:as:)`) and inserts the frame as one undo step; `importMedia` sends `.svg` files there. Hostile files are refused or read safely (`HostileImportTests`, 28 September 2026): entities that are files, web addresses, parameter entities or made of others are refused before parsing (`declaresRiskyEntities`; Illustrator's plain ones pass) and external entities are never loaded; nesting is counted from the bytes before `XMLDocument` sees them (`nesting(of:limit:)`), since the system's reader itself overflows its stack about a hundred thousand deep; past `maxDepth` (256, a `use` counting as a level) or `maxElements` (100,000 read, repeats included) the file is `ReadError.tooComplex`; a `use` never expands itself or what holds it (`expanding`); every number read goes through `SVGNumber.sane` (no `nan`, `inf` or anything past `limit`, a billion), and `Finite.layers` leaves out any layer whose place, size or points still ran past it, for Figma pastes too, whose polygons and stars keep at most `FigmaImport.maxPoints` (60, as the inspector).

## Performance

Performance is one of the most important parts of the tool. Measure before and after any change to evaluation, rendering, the canvas, the timeline or the panels:

```bash
cd Packages/MotionKit && TWINE_BENCH=1 swift test -c release --filter PerformanceTests
```

That prints per-frame timings for a 200-layer, 990-action scene (`stressProject` in `Tests/MotionRenderingTests/PerformanceTests.swift`; `TWINE_BENCH_OUT=path` writes it as a document to open in the app). In September 2026, release build: evaluate 1.06 ms (28 September, after walking only a layer's own channels; 1.2 before), still layout 0.4 ms, layer tree update 0.34 ms (0.30 before blend modes and path shadows), a 1080p offscreen frame 11.4 ms (14.6 before); in the app, playback 60 fps, a canvas drag step 6 to 8 ms, a timeline bar drag step 9 ms, a scrub step 4 ms, selecting a layer about 27 ms (SwiftUI building the inspector). Profile the running test copy with `sample <pid> 5` and read the main thread's call tree.

For very large projects (a Figma import of dozens of screens) there is a second scene, `largeProject` (5,050 layers in 50 frames, 550 actions on the first hundred or so layers), and an editing one (`LargeProjectTimings` in `Tests/MotionEditingTests`):

```bash
cd Packages/MotionKit && TWINE_BENCH=1 TWINE_BENCH_LARGE=1 swift test -c release --filter largeStages
cd Packages/MotionKit && TWINE_BENCH=1 swift test -c release --filter LargeProjectTimings
```

On 1 October 2026, release build: evaluate 1.8 ms a frame with an `EvaluationCache` (8.6 without), a design drag step's evaluation 1.5 ms, the layer tree update 2.1 ms (1.8 when nothing changed; it was 6.4), applying an edit 1.7 ms (4.3), finding a layer's place 0.15 ms (0.9), a 320-pixel thumbnail 170 ms, encoding the 13 MB file 120 ms. In the app (`Tools/SelfTest`, the large scene saved as `Large.twine` with its texts fitted, `perfdragat 700 450 40` and friends): playback 60 fps (25 before), a scrub step 8.6 ms (105), a press on the canvas 13 to 17 ms (5.8 seconds before), a drag step 22 to 27 ms (48 to 52), selecting about 30 to 40 ms (mostly the inspector, as in small projects), a save after the first 148 ms (307 to 446).

What keeps it fast, and must stay so: the canvas, the inspector's scene, the export preview and every export keep an `EvaluationCache` (pass it to `evaluate`/`evaluateDesign`): a layer no action reaches is resolved again only when it changed, and a still group (no action or mask anywhere in it) whose value is the same, children and all, hands back its whole run of resolved layers at once (unchanged lists compare at once, as they share storage); entries are classes, since copying a layer out of a dictionary cost more than resolving it. `CoreAnimationRenderer.render` reads layers by index and, while every layer is where it was under the same parent (`drawn`), skips rebuilding the tree; `Node.update` compares without wrapping the layer in an optional, which copied it. Walks of the layer tree use `Project.forEachLayer`, `location(of:)`, `parents`, `lockedLayers` and `isLocked(_:)`, which read layers in place: `allLayers` copies all of them (a millisecond at 5,000), and anything asking it, or `ancestors(of:)`, once per layer was seconds (pressing on the canvas gathered snap targets that way). `ResolvedScene`'s world transforms and `parentID(of:)` read in place too. Snapping keeps only candidates within reach and finds each gap's neighbour by halving. `TextLayout` keeps 4,096 layouts a generation (at 512, a project with 630 texts laid most out again every edit). A save leaves the thumbnail alone once drawing it took over 50 ms, and `ProjectDocument.close` draws it into the package (the home screen keys its cache on the thumbnail's date too). `ActionTracks.state` walks only the channels a layer has actions on, and copies no lists when all actions count (it used to walk all two dozen and filter each, which took evaluate from 1.06 ms to 1.25); `TextLayout` keeps the installed font families (`installed`, cleared with its caches on `kCTFontManagerRegisteredFontsChangedNotification`): asking Core Text for them took about 100 ms on the user's Mac and was done for every new style, 1.6 s of opening a project with 16 styles; `TextLayout` caches fonts and laid-out lines behind a `Mutex` (text is the dearest thing in a frame); `ResolvedScene` looks layers up through an index built once in `init`, so its lists are `let`; `CoreAnimationRenderer`'s `Node` skips a layer whose `ResolvedLayer` is unchanged (pictures and video always refresh); the timeline sorts small keys, not whole actions; ids compare by bytes (`UUID.precedes`), never by `uuidString`. Never do per-row or per-layer work that scans the whole project (the layers panel once checked every layer for masks in every row; `evaluate` once looked up every layer's mask by searching the project, 45.7 ms a frame for 1,000 layers with one mask, now 1.8 ms: masks are noted during the walk and `WorldTransforms` indexes layers and parents once). `TextLayout`'s layout cache keeps two generations of 512 (`Generations`), carrying what is found in the older into the newer, so a Counter's new entry every frame never flushes texts in use. The renderer keeps a shape's area (`Node.area(of:)`) and an inner shadow's last inputs, so shapes with pictures, updated every frame, do not redo boolean operations. After changing a stored property of a struct in MotionKit, run `swift package clean` (and delete `build/DerivedData` for the app): an incremental build can keep the old layout and crash in ways that look like real bugs.

Hover is shared: `EditorModel.hoveredLayer` is set by the canvas (`setHover`, which only clears its own) and by layers panel rows, and both draw it: the canvas in the selection's one-point accent line, following the layer's own shape as Figma does (`CanvasNSView.hoverOutline`: a shape's or frame's path, the box for text, groups and tilted layers; the user's choice on 29 September 2026, replacing a white line on a dark edge round the box), with no wash inside, nothing on a selected layer (the user wants only the selection box there), the row as its full hover state (`LayerRow.lit`, switches included).

SVGs in `Icons/`, 24x24, stroked, `M L H V C Z` only. A path's `opacity` attribute is kept (`Icon.opacities`, generated only for icons that have one; `IconView` draws each strength as its own `IconShape(opacity:)`), as the fill-linear icon's fading dots need; stroke widths are not, every line being drawn at `Theme.iconStroke`. The four `fill-...` icons (Solid, Linear, Radial, Image; the designer's, from `~/Desktop/29-09/Fill Icons`, 29 September 2026) label the fill kind segments through `Icon.fillKind`. Since 28 September 2026 every icon the app shows is the designer's (supplied in `~/Desktop/28-09`, copied in under the existing names; the music note's filled stem and flag were traced to a centre line, since icons are stroked); the ones no screen shows (most action icons, trash, export, filter, the keyframe and stopwatch ones) are still placeholders. The four `corner...` icons label the per-corner radius fields. The app draws every icon's line at `Theme.iconStroke` (1.92 on the grid, heavier than the artwork's 1.5; the user's choice), scaling with the icon, so a 20 pt icon has a 1.6 pt line. Regenerate after editing:

```bash
python3 Tools/svg_to_swift.py --icons Icons --out Packages/MotionKit/Sources/Theme/Icons.swift
```
