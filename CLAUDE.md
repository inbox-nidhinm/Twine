The app is called **Twine** (first called eMotion; renamed on 27 September 2026, and on 28 September 2026 the user asked for the old name to go everywhere). Everything says Twine: the repo folder `Documents/Claude Code/Twine`, the source folder `Twine/`, `Twine.xcodeproj` and its target and scheme, the bundle id `com.nidhin.twine` (test copy `com.nidhin.twine.selftest`, `build/TwineTest.app`), the pasteboard types, the `TWINE_` environment variables and `~/Documents/Twine Creations`. Projects end in `.twine` (`com.nidhin.twine.project`); the old `.emotion` type is no longer declared or read, as none were left. `App/FormerName.swift` is the only code with the old name: on the first launch as Twine it moves `~/Documents/eMotion Creations` to `Twine Creations` and copies the `com.nidhin.emotion` settings domain across (each only when the old exists and the new does not; never in the test copy). The version history keeps its two entries about the first rename as they were. The GitHub repo is `inbox-nidhinm/Twine`.

The original brief is `docs/brief.md`. The project is now working through a Jitter-style redesign: `docs/redesign.md` (the brief) and `docs/redesign-decisions.md` (answers, which win where they differ). Read both before a milestone. This file is the map and the rules.

## Rules

- **No em dashes anywhere**: UI strings, comments, docs, commit messages.
- No third-party dependencies without asking.
- Every milestone ends with: `./make-app.sh` with no warnings, `./test.sh` passing, the change written into the top build of `Twine/VersionHistory.swift` (see below), a commit, and a push to `inbox-nidhinm/Twine`.
- **Builds are releases, not changes** (30 September 2026, the user's request): `VersionHistory.builds` has about a dozen entries, each with `features`, `fixes` and `misc` lists (shown as Feature updates, Bug fixes and Misc, an empty list left out). Write each change as a line in the top build's list that fits it; start a new build (which raises the version number) only when the user says to cut one. Fold a change that undoes an earlier one in the same build into the final state. `VersionHistory.pushes` counts pushes to GitHub, the first being v0.0.01 and the 100th v0.1.00 (`release`, shown small beside the card's title): raise it by one in every commit you push. The build numbers in these notes ("build 43") are the old numbering, one per change, from before this.
- The user is a designer, not an engineer. Explain in plain terms.
- No help text in the UI. States are shown, not explained. Put explanations in `.help()` tooltips.
- Views never write literals: every colour, size and radius comes from `Theme` (in `Packages/MotionKit/Sources/Theme`). Values come from the "Flip Design System" page of Figma file `2XErpBfGuIGNU0DkL58Ute` (node 171:2055), with a light blue accent (#4C9FEF) in place of Flip's green.
- **Accessibility presses do not prove clicks work.** They skip hit testing. To test real clicks without touching the user's mouse, post `NSEvent` mouse and key events through `window.sendEvent` from a temporary in-app hook, and log state after each. After each step post an `.applicationDefined` event through `NSApp.postEvent`: events sent straight to a window skip the event loop, so the undo group never closes, the document never counts as edited, and nothing saves. Remove the hook before committing.
- **Posted events do not reliably reach SwiftUI gestures.** `onTapGesture` and `DragGesture` sometimes ignore events sent through `window.sendEvent` for a whole session, while real `Button`s always respond. Make clickable controls real buttons; for drags in SwiftUI views (the curve editor), set the value from the hook and say the drag itself was not exercised.
- **The save panel runs in another process.** A test hook can fill it in (`directoryURL` is ignored once it is up; set `NSNavLastRootDirectory` in the test copy's defaults instead) and close it with `window.endSheet(panel, returnCode: .OK)`; `panel.ok(nil)` throws. Errors are presented as sheets on the window (`presentError(_:modalFor:...)`) so they show in window captures.
- **`hitTest` takes a point in the view's superview's coordinates.** For the window's content view that is the frame view, which runs upward, while the content view runs downward, so `content.hitTest(content.convert(p, from: nil))` mirrors the point top to bottom. Use `ChromelessWindow.viewUnder(_:)`. A test hook that builds its points the same wrong way passes anyway: that is how canvas hover shipped broken over the top of the canvas in Animate.
- **A test copy's documents can become the user's work.** On 28 September 2026 the user kept working in a TwineTest window the kit had opened, and the next run wiped that project copy. `run.sh` now puts each run's copy in the run's own folder, moves an earlier run of the same name to the Bin, and asks TwineTest to quit (so it saves) before forcing it. Before a run, check whether TwineTest is open and whether its projects changed after the last run; if so, ask the user.
- **Never drive the copy of the app the user is using.** For scripted tests make a copy of `build/Twine.app` with its own bundle id (`com.nidhin.twine.selftest`) and point it at a throwaway project in the scratchpad.
- When driving the running app to verify, the user is often working in other apps. Launch with `open -g`, use accessibility presses (`click button N of ...`) rather than synthetic keys or clicks, and never type unless Twine is frontmost. Setting a SwiftUI text field's value through accessibility does not reach its binding.

## Decisions worth knowing

- **Undo is by snapshot.** `ProjectStore` records the whole `Project` before each command. Drags and sliders use `beginContinuousChange` / `updateContinuousChange` / `endContinuousChange` so they undo as one step. History is capped (28 September 2026): at most `ProjectStore.undoSteps` (200) steps, and about `undoBudget` (512 MB) of snapshots, each step's cost estimated when recorded (`cost(of:against:)`: the layer and action lists it copied; paths and words inside layers are not counted); past the budget the oldest steps go, by lowering the undo manager's `levelsOfUndo` for a moment. `undoCosts`/`redoCosts` follow undo and redo. `perform(_:joining:)` adds to the last step when it came from there with the same key and nothing has happened since (any other step, undo, redo or a continuous change clears `joinable`): typing uses it, so a change made between letters is its own step in order, rather than one change held open swallowing it.
- **Layers are stored back to front** (last in the array is in front). The layers panel shows them reversed.
- **Coordinates are Figma's**: origin top-left, y down, rotation clockwise in degrees (Figma's own rotation is counter-clockwise: an importer negates it). Anchor is in pixels from the layer's top-left. Scale 1 is 100%, opacity 0 to 1.
- **Skew and tilt** (28 September 2026): `Transform.skew` (degrees each way: x slants the sides, the bottom moving right; y the top and bottom) and `Transform.tilt` (`Tilt`: x tips around a level line through the anchor, top away; y turns around an upright one, right side away; `depth` is the viewing distance, 1200 by default), both left out of files when zero. A layer's flat transform is `Affine.layer(... skew:)` (scale, skew, rotation about the anchor), and every place that rebuilds one passes the skew, so resizing, anchors and grouping stay exact for skewed layers (ungrouping a skewed group loses its skew, as it loses an uneven stretch). A tilt is not flat: `Projective` (a 3 by 3 perspective matrix, exact for a flat layer turned in depth, which `caTransform` hands to Core Animation, so canvas, exports and thumbnails match; `WarpRenderingTests` checks pixels) with `Projective.layer` tilting after rotation. `ResolvedLayer.transform` stays flat (editing works in it); `.projection` and `ResolvedScene.worldProjection` are as drawn, and `worldCorners` (outlines, bounds, snapping), hit testing, clipping checks and `ResolvedMask.transform` follow them. A tilted layer, or anything in a tilted group, shows its outline but no handles (`CanvasNSView.isTilted`), since the handles' maths are flat; it is sized in the inspector. Dragging layers inside a tilted group is flat, so a little off. `Warp` boxes skew and tilt in `LayerState` and `ResolvedLayer` (an `indirect` case, `.none` for straight layers), as picture paints are, to keep states small. Skew and Tilt actions (`SkewAction`, `TiltAction`, To or By, the `skew` and `tilt` channels; By adds a tilt's angles and takes its depth) are offered wherever Move is. In the inspector they are Skew and Tilt entries in the Effects section (added from its + menu, shown while set; removing one zeroes it), Tilt with Depth once tilted.
- **Actions, not keyframes.** A layer's properties are plain values: its design state. `Project.actions` is a flat list; each `Action` targets one layer, has a start, a duration (0 is instant), an easing, and an `ActionSpec` carrying its own typed optional initial value and end value. Layers have no in or out points.
- **The action rules live in one place**: `walk` in `MotionEvaluation/ActionTracks.swift`, with its numbered comment. Each action drives one channel (position, scale, rotation, opacity, size, visibility). On one channel of one layer, actions go in start order (ties by `rowOrder`); an empty initial value inherits the value at the action's start; the first action's explicit initial value holds from time 0 (entrances); a later action takes over from the value at its own start. Channels never interfere. By mode adds (Scale By multiplies); To is absolute. Resize grows around the anchor. A layer is shown until something hides it: a Show never hides what comes before it (the user's choice on 28 September 2026; it used to hide the layer until it when it was the first). Show and Hide are kept whatever else the layer does (rule 10, the user's choice on 28 September 2026, as in Jitter): a Show or Hide at or before a channel's first action stops that action's starting value holding from 0 s, so a layer shown at 1 s with a Fade In at 3 s shows as designed until 3 s; a Show brings back a layer faded right out (opacity only, to its design; `withShows`, a `revive` step), letters faded out by a text preset too; an In preset (`PresetKind.entering`, now in MotionModel) counts as a Show on the visibility track of a layer that has a Show or Hide, so one after a Hide plays.
- **Easing** is a named preset with an intensity or a custom bezier. The presets are Jitter's (28 September 2026): Smooth, Natural, Slow down, Accelerate, Elastic (stored as `spring`), Bounce, Overshoot, Impulse, Swing and Linear (stored as `none`). Presets are worked out at evaluation, so improving one improves every action. At the standard intensity (0.5) each is exactly the designer's curve: the four beziers in `designCurve`, the rest CSS `linear()` lists of 101 points in `EasingTables` (MotionEvaluation). Lower intensity fades a preset towards a straight line (a bezier by drawing its handles in); higher strengthens it (a bezier towards itself applied twice, a list by doubling how far it strays from the line, Bounce by deepening its bounces after it first lands). `Spring` is no longer used by a preset.
- **Actions follow their layers**: `EditorCommand.apply` drops actions whose layer is gone, whatever command removed it, and clears masks that name a layer that is gone, once the whole command is done, so a batch that takes a layer out and puts it back (ungrouping) keeps masks naming it, and a paste from another project drops masks it left behind. A copy is the layer whole under a new id (`Layer.withID`; copying field by field once lost blend modes and the proportions link), with new ids for its fills, strokes and effects; layers copied together have their masks pointed at each other's copies (`remappingMasks`, after every copy has its id). Carrying a layer through a flipped group (a negative scale, `Arrangement.mirrors`) turns its rotation and skew the other way, and its actions' (`remapped(mirrored:)`). Times are held to `Composition.longest` (a day) by the commands and the Duration field, and frame numbers are made whole through `FrameRate.whole`, so no typed time can crash; a damaged file's frame rate of 0 reads as 30. Grouping and ungrouping remap To values and initial values into the new parent space (`Action.remapped`); duplicating and pasting copy actions through `duplicated(recordingIDs:)` and `actionCopies(for:)`.
- **File format 2** is the first with actions. Anything older is refused with a plain message (`ProjectFileError.olderVersion`, whose `failureReason` is what the open alert shows). **Format 3** made pictures fills: `PictureMigration` (in `FileFormat.swift`, on the raw JSON) turns each old picture layer into a rectangle with an image fill, keeping its id, so actions and masks carry on; one stretched out of its picture's shape becomes a Crop of the whole box, so it looks the same. Opening an old file does not rewrite it until it is edited.
- **Frames** are groups with a look: `GroupContent.frame` (`FrameStyle`: fills, strokes, corner radii; nil for a plain group), so everything groups do (nesting, grouping, ungrouping, carrying actions) holds. `Layer.isFrame`; `Layer.look` is the fills, strokes and outline of a shape, or of a frame as a rectangle, and is what the inspector's Fill and Stroke sections, `LayerState(design:)`, pictures and cropping read and write. `evaluate` resolves a frame's look into `ResolvedLayer.frame`; `ResolvedScene.bounds(of:)` is a frame's own box. The renderer's `Node` keeps a group's children in `children`, a holder inside the container, clipped there (to the box for a group, to the frame's outline by `clipMask`), so a clipping group keeps its shadow; a frame's container holds its fills, then the holder, then its strokes (`updateShape(around:)`). Frames resize (`CanvasGeometry.resized`), are hit on their own fill and stroke, and take Resize, Colour, Stroke, Corner Radius and the blurs (`ActionFactory`); hit testing honours any clipping parent (`shows`). `LayerFactory.frame` is Figma's default (white, clipping). The Frame tool (`Tool.frame`, F, `Tool.draws`) draws one, and at mouse up takes in the siblings wholly inside it (`Arrangement.enclosed`, `adopt`); anything drawn with a press inside a frame goes into the innermost one (`CanvasNSView.frame(under:)`, `Arrangement.placed`), text too. `Arrangement.group(asFrame:)` is Frame Selection (⌥⌘G). Grouping moves layers in with `.moveLayers` rather than deleting and reinserting them, since deleting clears masks that name them. `Arrangement.move` (the layers panel's drops) keeps layers in place on screen across parents, carrying their actions.
- **Blend modes and shadows**: `Layer.blendMode` (Figma's list, `BlendMode.groups` for the menu; left out of the file at Normal) is the container's `compositingFilter` from `Blending` (Core Animation's private filters by name; all 17 match the W3C formulas Figma uses to within 3% in `BlendRenderingTests`, except Soft Light, Pegtop's formula, up to 5% darker in dark colours; Core Image's was further off). A group at Normal passes its children's blending through, as Figma's Pass Through. The composition's background is the renderer's `contentLayer`'s own colour, under the layers: a blend only sees what is drawn in its own superlayer, and while the background was a layer beside them (until 29 September 2026) every mode drew as Normal over it (`blendModesBlendWithTheBackground`). A mask's own node ignores blend (`ignoresBlend`). `EffectKind.innerShadow` (shapes and frames). `ResolvedLayer.shadows` lists every drop shadow on, the first carrying the Shadow action (`state.shadow`); `innerShadows` likewise, not animated. A shape or frame that draws casts all its shadows from its outline (fills and strokes as regions, `Node.outline`, cached by look), each a `ShadowLayer` drawing only its shadow with the outline knocked out, at the fills' strength (`Node.strength`: a 25% card casts a 25% shadow), as Figma does; text, video, plain groups and frames that draw nothing keep one shadow on the container, from what they draw. An `InnerShadowLayer` is a sheet with the outline (shrunk by spread) cut out, casting inward, masked to the outline, over the fills. `Node.arrange` stacks a shape's or frame's sublayers (shadows, backdrop, fills, inner shadows, a frame's children, strokes), rebuilding only when their counts change.
- **The Figma plugin** (`FigmaPlugin/`, its README says how it is added and built): `code.js` describes the selection as a `twine.figma` payload (JSON on the clipboard, copied by the panel through a hidden text box), each layer with its absolute transform so Figma's groups need no care, and flattens what Twine cannot hold while Figma can still draw it: `picture` (PNG at 2×, placed at its render bounds) for mixed-style, italic, decorated or list text, angular and diamond gradients, picture filters or odd turns, luminance masks and unknown types; `svg` (Figma's SVG, read by `SVGImport` into a group) for vectors with painted regions or mixed winding, smoothed rectangles and rounded polygons. Frames are never flattened (their children would be); a paint they cannot keep and uneven borders are left out with a `warnings` line. A layer keeps one picture fill, the topmost shown (`keptPaints` in the plugin, so the others are not copied, and `FigmaImport.fills`): pictures stacked under it cannot be seen. A frame's picture background comes in as its own `Background` picture layer at the bottom of the frame, its size and corners, with any fills Figma drew over it (`FigmaImport.background`), so it shows in the layers panel; the fills under it stay the frame's. `FigmaImport` (MotionImport) builds the layers: transforms into each parent's space (Figma's turn is anticlockwise, so the matrix's own `atan2(b, a)` is Twine's; `place` splits any matrix into Twine's turn, skew across and scale, so skewed layers, frames and text come in as themselves since 28 September 2026, and the plugin no longer flattens them), masks over the siblings in front of them, gradients and picture crops through the inverse of Figma's transforms, font style names to weights, fonts this Mac lacks noted. `EditorController.pasteFromFigma` (from Paste when the clipboard string is a payload): it is centred at its exact size, never shrunk, and the composition is never resized to fit it, even when empty (both the user's choice; the empty-project resize went on 28 September 2026); pictures are staged and reused by hash; one undo step; missing fonts and warnings go to `EditorModel.showNotice` (`NoticeCard`, six seconds). The notice is a `Notice` (text and a state: a note, work under way with an optional fraction, or done). Imports follow their work through it (the user's request, 30 September 2026): `beginWork(_:after:)` (0.4 s, so quick imports show nothing; at once for a WebM) shows a `Loader` ring, `updateWork` sets the text and how far (a WebM's conversion from ffmpeg's `-progress` lines, `out_time_us` against the probed duration), `finishWork(done:)` shows a check and the done text for three seconds, or with nil clears it; `showNotice` drops any work so an error is never written over, and the close button (`dismissNotice`) hides the work's notice for good. `FigmaPlugin/test/run.js` runs `code.js` on a stand-in for Figma and writes `test/sample-payload.json`, which `FigmaPluginSampleTests` reads. The panel is drawn as the app's panels are (28 September 2026; the design is on Page 3, "Twine plugin states", of Figma file `RRnath7INm7WH7CGLOfLdH`): a floating panel on the canvas colour with no header (Figma's window title says Twine), a preview well showing the selection as Figma draws it (`sendPreview`: each selected layer exported as PNG and laid out where it sits, newest selection wins), its name with its size and layer count, and the blue Copy button; copying shows a PP Kyoto percentage and a progress bar, and a copy a check in the well's top-right corner. `ui.src.html` is built into `ui.html` by `build.py`. Figma's manifest has no icon field, so a development plugin shows Figma's own icon; `FigmaPlugin/icon.png` (the app icon at 128) is for the publish dialog, the only place an icon is set. Figma reads a development plugin's files from its folder on every run; moving the folder means importing the manifest again (the rename to Twine did). Not yet run inside Figma.
- **SVG import** (`MotionImport`, tested in `MotionImportTests`, including a pixel comparison of Twine's drawing against the system's): the file is read with `XMLDocument` and walked with each element's full transform, so every layer is made in the SVG's own space, scaled to its final size (fitted to the composition), and the file comes in as a frame (no fill, clipping, as a viewport does) named after it. Rectangles and ellipses whose transform only moves, turns and scales keep their kind; everything else becomes a path drawn through its transform (`SVGPathData`: every command, quadratics raised, arcs cut into quarter-turn cubics). Styles follow SVG's order (attributes, `.class` rules from `<style>`, `style`), inheriting what inherits. Gradients (either units, `href` chains, `gradientTransform`) are mapped into the layer's box; `fill-rule` becomes `ShapeContent.fillRule` (even-odd is drawn with the rule and normalised into a plain area, `ResolvedShape.area`, wherever paths are cut or joined); groups of one with nothing of their own flatten. `clip-path` and alpha (or white luminance) masks become a mask layer before the masked one; both at once, or a mask Twine cannot draw, and the element becomes a picture. Figma's filters are read by their result names (`SVGFilters`) into drop and inner shadows and layer blur; its background blur comes from the `foreignObject` before the shape. Figma's picture fills (a `pattern` of one `use` of an embedded `image`) become picture fills with the crop; plain `<image>`s become picture rectangles. Text is drawn by `SVGPictures` (AppKit's own SVG drawing, which draws no filters, misplaces positioned `tspan`s, so each becomes a `<text>`, and reads font weights only as numbers) from an SVG of just that element inside its ancestors' styles, with every definition, trimmed to its ink and placed there as a picture. `Result.reusing` swaps in pictures the project has. `EditorController.importSVG` stages the pictures (`ProjectDocument.stage(_ data:as:)`) and inserts the frame as one undo step; `importMedia` sends `.svg` files there. Hostile files are refused or read safely (`HostileImportTests`, 28 September 2026): entities that are files, web addresses, parameter entities or made of others are refused before parsing (`declaresRiskyEntities`; Illustrator's plain ones pass) and external entities are never loaded; nesting is counted from the bytes before `XMLDocument` sees them (`nesting(of:limit:)`), since the system's reader itself overflows its stack about a hundred thousand deep; past `maxDepth` (256, a `use` counting as a level) or `maxElements` (100,000 read, repeats included) the file is `ReadError.tooComplex`; a `use` never expands itself or what holds it (`expanding`); every number read goes through `SVGNumber.sane` (no `nan`, `inf` or anything past `limit`, a billion), and `Finite.layers` leaves out any layer whose place, size or points still ran past it, for Figma pastes too, whose polygons and stars keep at most `FigmaImport.maxPoints` (60, as the inspector).
- **Pictures are fills**, as in Figma: there is no picture layer. `Paint.image(ImagePaint)` (media id, `ImageScaleMode` fill, fit, crop or tile, `crop` as an `ImageCrop` in fractions of the box, `quarterTurns`, `tileScale`, `opacity`) is `indirect`, as is `ResolvedPaint.image`, because a larger paint made every layer state dearer to copy (evaluate went from 1.18 to 1.35 ms until it was boxed). `ImagePlacement` (MotionEvaluation, tested) is the only place a picture's box is worked out, from `Project.pictureSizes` (the assets' pixel sizes): every box is the picture after its turns. `evaluate` hands the renderer `ResolvedImage` (frame, turns, tiles, opacity); `PaintLayers` draws it in a holder masked by the shape, tiles with two `CAReplicatorLayer`s (at most 256 a side), and shapes with a picture skip `Node`'s unchanged check, as video does. Strokes never take a picture; a Colour action is not offered when the first fill is one, and picture paints hold rather than blend. `Layer.picture` is the first picture fill, which the inspector (`PictureFields`), Replace and cropping use; `Layer.mediaIDs` lists every file a layer uses. `LayerFactory.media` makes a picture a rectangle filled with it.
- **Replace and cropping**: `PictureEditing` (MotionEditing, tested) holds the maths: `replacingPicture` (a crop keeps its centre and covers what showed, in the new picture's shape; a layer still named after its old file takes the new name), `replacingVideo` (pulls a play's `trimStart` back so it ends by the new clip's end), `settingMode` (into Crop, the crop that shows the picture where it was), `turned`, `movedCrop`, `scaledCrop` (keeps shape, opposite corner fixed), `croppingResize` (box handles crop, the picture stays put). `EditorController.replaceMedia(of:)` opens the panel; `replaceMedia(of:with:)` and `fillWithPicture(_:from:)` take a URL (the test kit calls these) and `bringIn` reuses a file already in the project by its hash. Cropping is `Canvas/CanvasCropping.swift`: a `CropSession`, entered by `setPictureMode(.crop)` (the inspector) or a double-click on a picture, left by Escape, Return, a click away from the picture and the box, or `validateCropSession` (selection, mode, tool). Presses are `CanvasDrag.CropEdit` (move, a picture corner, a box handle); picture corners win where they meet the box's. The overlay draws the whole picture at `CanvasOverlay.cropPictureOpacity` in `cropHolder` (the overlay sizes its own sublayers), a dashed outline and corner squares. Videos have `VideoContent.fit` (Fill or Fit, `contentsGravity`), decoded as Fill from older files.
- **Fills, strokes and effects are lists** so a Figma import keeps everything. ## Performance

Performance is one of the most important parts of the tool. Measure before and after any change to evaluation, rendering, the canvas, the timeline or the panels:

```bash
cd Packages/MotionKit && TWINE_BENCH=1 swift test -c release --filter PerformanceTests
```

That prints per-frame timings for a 200-layer, 990-action scene (`stressProject` in `Tests/MotionRenderingTests/PerformanceTests.swift`; `TWINE_BENCH_OUT=path` writes it as a document to open in the app). In September 2026, release build: evaluate 1.06 ms (28 September, after walking only a layer's own channels; 1.2 before), still layout 0.4 ms, layer tree update 0.34 ms (0.30 before blend modes and path shadows), a 1080p offscreen frame 11.4 ms (14.6 before); in the app, playback 60 fps, a canvas drag step 6 to 8 ms, a timeline bar drag step 9 ms, a scrub step 4 ms, selecting a layer about 27 ms (SwiftUI building the inspector). Profile the running test copy with `sample <pid> 5` and read the main thread's call tree.

What keeps it fast, and must stay so: `ActionTracks.state` walks only the channels a layer has actions on, and copies no lists when all actions count (it used to walk all two dozen and filter each, which took evaluate from 1.06 ms to 1.25); `TextLayout` caches fonts and laid-out lines behind a `Mutex` (text is the dearest thing in a frame); `ResolvedScene` looks layers up through an index built once in `init`, so its lists are `let`; `CoreAnimationRenderer`'s `Node` skips a layer whose `ResolvedLayer` is unchanged (pictures and video always refresh); the timeline sorts small keys, not whole actions; ids compare by bytes (`UUID.precedes`), never by `uuidString`. Never do per-row or per-layer work that scans the whole project (the layers panel once checked every layer for masks in every row; `evaluate` once looked up every layer's mask by searching the project, 45.7 ms a frame for 1,000 layers with one mask, now 1.8 ms: masks are noted during the walk and `WorldTransforms` indexes layers and parents once). `TextLayout`'s layout cache keeps two generations of 512 (`Generations`), carrying what is found in the older into the newer, so a Counter's new entry every frame never flushes texts in use. The renderer keeps a shape's area (`Node.area(of:)`) and an inner shadow's last inputs, so shapes with pictures, updated every frame, do not redo boolean operations. After changing a stored property of a struct in MotionKit, run `swift package clean` (and delete `build/DerivedData` for the app): an incremental build can keep the old layout and crash in ways that look like real bugs.
