# Twine: notes for working on it

The app is called **Twine** (first called eMotion; renamed on 27 September 2026, and on 28 September 2026 the user asked for the old name to go everywhere). Everything says Twine: the repo folder `Documents/Claude Code/Twine`, the source folder `Twine/`, `Twine.xcodeproj` and its target and scheme, the bundle id `com.nidhin.twine` (test copy `com.nidhin.twine.selftest`, `build/TwineTest.app`), the pasteboard types, the `TWINE_` environment variables and `~/Documents/Twine Creations`. Projects end in `.twine` (`com.nidhin.twine.project`); the old `.emotion` type is no longer declared or read, as none were left. `App/FormerName.swift` is the only code with the old name: on the first launch as Twine it moves `~/Documents/eMotion Creations` to `Twine Creations` and copies the `com.nidhin.emotion` settings domain across (each only when the old exists and the new does not; never in the test copy). The version history keeps its two entries about the first rename as they were. The GitHub repo is `inbox-nidhinm/Twine`.

The original brief is `docs/brief.md`. The project is now working through a Jitter-style redesign: `docs/redesign.md` (the brief) and `docs/redesign-decisions.md` (answers, which win where they differ). Read both before a milestone. This file is the map and the rules.

## Rules

- **No em dashes anywhere**: UI strings, comments, docs, commit messages.
- No third-party dependencies without asking.
- Every milestone ends with: `./make-app.sh` with no warnings, `./test.sh` passing, a new entry at the top of `Twine/VersionHistory.swift`, a commit, and a push to `inbox-nidhinm/Twine`.
- The user is a designer, not an engineer. Explain in plain terms.
- No help text in the UI. States are shown, not explained. Put explanations in `.help()` tooltips.
- Views never write literals: every colour, size and radius comes from `Theme` (in `Packages/MotionKit/Sources/Theme`). Values come from the "Flip Design System" page of Figma file `2XErpBfGuIGNU0DkL58Ute` (node 171:2055), with a light blue accent (#4C9FEF) in place of Flip's green.
- **Accessibility presses do not prove clicks work.** They skip hit testing. To test real clicks without touching the user's mouse, post `NSEvent` mouse and key events through `window.sendEvent` from a temporary in-app hook, and log state after each. After each step post an `.applicationDefined` event through `NSApp.postEvent`: events sent straight to a window skip the event loop, so the undo group never closes, the document never counts as edited, and nothing saves. Remove the hook before committing.
- **Posted events do not reliably reach SwiftUI gestures.** `onTapGesture` and `DragGesture` sometimes ignore events sent through `window.sendEvent` for a whole session, while real `Button`s always respond. Make clickable controls real buttons; for drags in SwiftUI views (the curve editor), set the value from the hook and say the drag itself was not exercised.
- **The save panel runs in another process.** A test hook can fill it in (`directoryURL` is ignored once it is up; set `NSNavLastRootDirectory` in the test copy's defaults instead) and close it with `window.endSheet(panel, returnCode: .OK)`; `panel.ok(nil)` throws. Errors are presented as sheets on the window (`presentError(_:modalFor:...)`) so they show in window captures.
- **`hitTest` takes a point in the view's superview's coordinates.** For the window's content view that is the frame view, which runs upward, while the content view runs downward, so `content.hitTest(content.convert(p, from: nil))` mirrors the point top to bottom. Use `ChromelessWindow.viewUnder(_:)`. A test hook that builds its points the same wrong way passes anyway: that is how canvas hover shipped broken over the top of the canvas in Animate.
- **Never drive the copy of the app the user is using.** For scripted tests make a copy of `build/Twine.app` with its own bundle id (`com.nidhin.twine.selftest`) and point it at a throwaway project in the scratchpad.
- When driving the running app to verify, the user is often working in other apps. Launch with `open -g`, use accessibility presses (`click button N of ...`) rather than synthetic keys or clicks, and never type unless Twine is frontmost. Setting a SwiftUI text field's value through accessibility does not reach its binding.

## Decisions worth knowing

- **Undo is by snapshot.** `ProjectStore` records the whole `Project` before each command. Drags and sliders use `beginContinuousChange` / `updateContinuousChange` / `endContinuousChange` so they undo as one step.
- **Layers are stored back to front** (last in the array is in front). The layers panel shows them reversed.
- **Coordinates are Figma's**: origin top-left, y down, rotation clockwise in degrees (Figma's own rotation is counter-clockwise: an importer negates it). Anchor is in pixels from the layer's top-left. Scale 1 is 100%, opacity 0 to 1.
- **Actions, not keyframes.** A layer's properties are plain values: its design state. `Project.actions` is a flat list; each `Action` targets one layer, has a start, a duration (0 is instant), an easing, and an `ActionSpec` carrying its own typed optional initial value and end value. Layers have no in or out points.
- **The action rules live in one place**: `walk` in `MotionEvaluation/ActionTracks.swift`, with its numbered comment. Each action drives one channel (position, scale, rotation, opacity, size, visibility). On one channel of one layer, actions go in start order (ties by `rowOrder`); an empty initial value inherits the value at the action's start; the first action's explicit initial value holds from time 0 (entrances); a later action takes over from the value at its own start. Channels never interfere. By mode adds (Scale By multiplies); To is absolute. Resize grows around the anchor. A first Show hides the layer until it.
- **Easing** is a named preset with an intensity (none, smooth, slow down, accelerate, overshoot, spring) or a custom bezier. Presets are worked out at evaluation, so improving one improves every action. A spring's motion is fitted to the action's duration.
- **Actions follow their layers**: `EditorCommand.apply` drops actions whose layer is gone, whatever command removed it. Grouping and ungrouping remap To values and initial values into the new parent space (`Action.remapped`); duplicating and pasting copy actions through `duplicated(recordingIDs:)` and `actionCopies(for:)`.
- **File format 2** is the first with actions. Anything older is refused with a plain message (`ProjectFileError.olderVersion`, whose `failureReason` is what the open alert shows). **Format 3** made pictures fills: `PictureMigration` (in `FileFormat.swift`, on the raw JSON) turns each old picture layer into a rectangle with an image fill, keeping its id, so actions and masks carry on; one stretched out of its picture's shape becomes a Crop of the whole box, so it looks the same. Opening an old file does not rewrite it until it is edited.
- **Frames** are groups with a look: `GroupContent.frame` (`FrameStyle`: fills, strokes, corner radii; nil for a plain group), so everything groups do (nesting, grouping, ungrouping, carrying actions) holds. `Layer.isFrame`; `Layer.look` is the fills, strokes and outline of a shape, or of a frame as a rectangle, and is what the inspector's Fill and Stroke sections, `LayerState(design:)`, pictures and cropping read and write. `evaluate` resolves a frame's look into `ResolvedLayer.frame`; `ResolvedScene.bounds(of:)` is a frame's own box. The renderer's `Node` keeps a group's children in `children`, a holder inside the container, clipped there (to the box for a group, to the frame's outline by `clipMask`), so a clipping group keeps its shadow; a frame's container holds its fills, then the holder, then its strokes (`updateShape(around:)`). Frames resize (`CanvasGeometry.resized`), are hit on their own fill and stroke, and take Resize, Colour, Stroke, Corner Radius and the blurs (`ActionFactory`); hit testing honours any clipping parent (`shows`). `LayerFactory.frame` is Figma's default (white, clipping). The Frame tool (`Tool.frame`, F, `Tool.draws`) draws one, and at mouse up takes in the siblings wholly inside it (`Arrangement.enclosed`, `adopt`); anything drawn with a press inside a frame goes into the innermost one (`CanvasNSView.frame(under:)`, `Arrangement.placed`), text too. `Arrangement.group(asFrame:)` is Frame Selection (⌥⌘G). Grouping moves layers in with `.moveLayers` rather than deleting and reinserting them, since deleting clears masks that name them. `Arrangement.move` (the layers panel's drops) keeps layers in place on screen across parents, carrying their actions.
- **Blend modes and shadows**: `Layer.blendMode` (Figma's list, `BlendMode.groups` for the menu; left out of the file at Normal) is the container's `compositingFilter` from `Blending` (Core Animation's private filters by name; all 17 match the W3C formulas Figma uses to within 3% in `BlendRenderingTests`, except Soft Light, Pegtop's formula, up to 5% darker in dark colours; Core Image's was further off). A group at Normal passes its children's blending through, as Figma's Pass Through. A mask's own node ignores blend (`ignoresBlend`). `EffectKind.innerShadow` (shapes and frames). `ResolvedLayer.shadows` lists every drop shadow on, the first carrying the Shadow action (`state.shadow`); `innerShadows` likewise, not animated. A shape or frame that draws casts all its shadows from its outline (fills and strokes as regions, `Node.outline`, cached by look), each a `ShadowLayer` drawing only its shadow with the outline knocked out, at the fills' strength (`Node.strength`: a 25% card casts a 25% shadow), as Figma does; text, video, plain groups and frames that draw nothing keep one shadow on the container, from what they draw. An `InnerShadowLayer` is a sheet with the outline (shrunk by spread) cut out, casting inward, masked to the outline, over the fills. `Node.arrange` stacks a shape's or frame's sublayers (shadows, backdrop, fills, inner shadows, a frame's children, strokes), rebuilding only when their counts change.
- **The Figma plugin** (`FigmaPlugin/`, its README says how it is added and built): `code.js` describes the selection as a `twine.figma` payload (JSON on the clipboard, copied by the panel through a hidden text box), each layer with its absolute transform so Figma's groups need no care, and flattens what Twine cannot hold while Figma can still draw it: `picture` (PNG at 2×, placed at its render bounds) for mixed-style, italic, decorated or list text, angular and diamond gradients, picture filters or odd turns, luminance masks, skews and unknown types; `svg` (Figma's SVG, read by `SVGImport` into a group) for vectors with painted regions or mixed winding, smoothed rectangles and rounded polygons. Frames are never flattened (their children would be); a paint they cannot keep and uneven borders are left out with a `warnings` line. `FigmaImport` (MotionImport) builds the layers: transforms into each parent's space (Figma's turn is anticlockwise, so the matrix's own `atan2(b, a)` is Twine's), masks over the siblings in front of them, gradients and picture crops through the inverse of Figma's transforms, font style names to weights, fonts this Mac lacks noted. `EditorController.pasteFromFigma` (from Paste when the clipboard string is a payload): into an empty project the composition takes the copy's size and it lines up; otherwise it is centred at its exact size, never shrunk (the user's choice); pictures are staged and reused by hash; one undo step; missing fonts and warnings go to `EditorModel.showNotice` (`NoticeCard`, six seconds). `FigmaPlugin/test/run.js` runs `code.js` on a stand-in for Figma and writes `test/sample-payload.json`, which `FigmaPluginSampleTests` reads. The panel matches the user's four mockups (no grain; white glass card at 10%); `ui.src.html` is built into `ui.html` by `build.py`. Figma's manifest has no icon field, so a development plugin shows Figma's own icon; `FigmaPlugin/icon.png` (the app icon at 128) is for the publish dialog, the only place an icon is set. Figma reads a development plugin's files from its folder on every run; moving the folder means importing the manifest again (the rename to Twine did). Not yet run inside Figma.
- **SVG import** (`MotionImport`, tested in `MotionImportTests`, including a pixel comparison of Twine's drawing against the system's): the file is read with `XMLDocument` and walked with each element's full transform, so every layer is made in the SVG's own space, scaled to its final size (fitted to the composition), and the file comes in as a frame (no fill, clipping, as a viewport does) named after it. Rectangles and ellipses whose transform only moves, turns and scales keep their kind; everything else becomes a path drawn through its transform (`SVGPathData`: every command, quadratics raised, arcs cut into quarter-turn cubics). Styles follow SVG's order (attributes, `.class` rules from `<style>`, `style`), inheriting what inherits. Gradients (either units, `href` chains, `gradientTransform`) are mapped into the layer's box; `fill-rule` becomes `ShapeContent.fillRule` (even-odd is drawn with the rule and normalised into a plain area, `ResolvedShape.area`, wherever paths are cut or joined); groups of one with nothing of their own flatten. `clip-path` and alpha (or white luminance) masks become a mask layer before the masked one; both at once, or a mask Twine cannot draw, and the element becomes a picture. Figma's filters are read by their result names (`SVGFilters`) into drop and inner shadows and layer blur; its background blur comes from the `foreignObject` before the shape. Figma's picture fills (a `pattern` of one `use` of an embedded `image`) become picture fills with the crop; plain `<image>`s become picture rectangles. Text is drawn by `SVGPictures` (AppKit's own SVG drawing, which draws no filters, misplaces positioned `tspan`s, so each becomes a `<text>`, and reads font weights only as numbers) from an SVG of just that element inside its ancestors' styles, with every definition, trimmed to its ink and placed there as a picture. `Result.reusing` swaps in pictures the project has. `EditorController.importSVG` stages the pictures (`ProjectDocument.stage(_ data:as:)`) and inserts the frame as one undo step; `importMedia` sends `.svg` files there.
- **Pictures are fills**, as in Figma: there is no picture layer. `Paint.image(ImagePaint)` (media id, `ImageScaleMode` fill, fit, crop or tile, `crop` as an `ImageCrop` in fractions of the box, `quarterTurns`, `tileScale`, `opacity`) is `indirect`, as is `ResolvedPaint.image`, because a larger paint made every layer state dearer to copy (evaluate went from 1.18 to 1.35 ms until it was boxed). `ImagePlacement` (MotionEvaluation, tested) is the only place a picture's box is worked out, from `Project.pictureSizes` (the assets' pixel sizes): every box is the picture after its turns. `evaluate` hands the renderer `ResolvedImage` (frame, turns, tiles, opacity); `PaintLayers` draws it in a holder masked by the shape, tiles with two `CAReplicatorLayer`s (at most 256 a side), and shapes with a picture skip `Node`'s unchanged check, as video does. Strokes never take a picture; a Colour action is not offered when the first fill is one, and picture paints hold rather than blend. `Layer.picture` is the first picture fill, which the inspector (`PictureFields`), Replace and cropping use; `Layer.mediaIDs` lists every file a layer uses. `LayerFactory.media` makes a picture a rectangle filled with it.
- **Replace and cropping**: `PictureEditing` (MotionEditing, tested) holds the maths: `replacingPicture` (a crop keeps its centre and covers what showed, in the new picture's shape; a layer still named after its old file takes the new name), `replacingVideo` (pulls a play's `trimStart` back so it ends by the new clip's end), `settingMode` (into Crop, the crop that shows the picture where it was), `turned`, `movedCrop`, `scaledCrop` (keeps shape, opposite corner fixed), `croppingResize` (box handles crop, the picture stays put). `EditorController.replaceMedia(of:)` opens the panel; `replaceMedia(of:with:)` and `fillWithPicture(_:from:)` take a URL (the test kit calls these) and `bringIn` reuses a file already in the project by its hash. Cropping is `Canvas/CanvasCropping.swift`: a `CropSession`, entered by `setPictureMode(.crop)` (the inspector) or a double-click on a picture, left by Escape, Return, a click away from the picture and the box, or `validateCropSession` (selection, mode, tool). Presses are `CanvasDrag.CropEdit` (move, a picture corner, a box handle); picture corners win where they meet the box's. The overlay draws the whole picture at `CanvasOverlay.cropPictureOpacity` in `cropHolder` (the overlay sizes its own sublayers), a dashed outline and corner squares. Videos have `VideoContent.fit` (Fill or Fit, `contentsGravity`), decoded as Fill from older files.
- **Fills, strokes and effects are lists** so a future Figma import keeps everything. The MVP UI edits the first.
- **Paths are plain data** (`BezierPath`), for SVG import, boolean operations and morphing later. A pen path (`.path` geometry) fills its layer's box like every other shape: `BezierPath.fitted(from: bounds, to: size)` stretches the stored points' curve bounds (`BezierPath.bounds`, true extrema, not handles) onto the box, in `resolve` and in `ShapeGeometry.bezierPath(size:)`. Editing points keeps the stored bounds equal to the box (`PathEditing.reshaped`), so the stretch is only ever non-trivial after a resize.
- **The pen and point editing** (`Canvas/CanvasPathEditing.swift`, maths in `MotionEditing/PathEditing.swift`, tested): the canvas keeps a `PathSession` (the layer, its target, `.layer` in Design or `.action(id)` for a Path action in Animate, the picked `PointRef`s, and while drawing the open end `drawingFrom`). `validatePathSession` (from `show`) drops it when the selection, mode or tool moves on, and makes one whenever a single Path action is the `canvasAction`; it never writes to the model (finishing a drawing is sent on a turn later). Presses are `CanvasDrag.PathEdit`s that work from the path, layer and actions as they were at the press, with a 3-point dead zone so clicks never sprout handles. Every change to a layer's points goes through `PathEditing.reshaped(_:to:actions:)`: the box refits to the curves, the anchor keeps its fraction, the position moves so nothing shifts, `layerUpdate` carries Move actions, and the layer's Path actions are carried into the new space. Each pen click is its own undo step (begin at the press, end at release); the session re-reads the project, so undo mid-drawing just carries on from the new end. A new path is styled as a line (`LayerFactory.lineStroke`) and takes the default fill when closed, unless restyled (`styledForClosing`). The overlay draws points, handles and the pen's following segment (`CanvasOverlay.updatePath`); in Design the edited layer's box and handles hide. A Path action (`PathAction`, `path` channel) blends point by point and holds when point counts differ; its end is edited on the canvas at the layer's end-of-action place (`pathTransform`), points may move but not be added or deleted (Delete beeps). The test kit's `path xy` step logs points and their window coordinates.
- **One window** (`App/MainWindow.swift`): the app has a single `ChromelessWindow`, kept for its whole life (`isReleasedWhenClosed` false, frame saved as "Main"), showing Home or one project's editor. It is handed between window controllers, since each `NSDocument` wants its own: `MainWindow.take(then:)` frees it from whoever has it (an `EditorWindowController` `leave`s: stops playback, menus and export, drops the window, removes itself from its document and calls `ProjectDocument.closeAfterSaving`, which autosaves first because closing a document directly would not), and `present(_:in:)` fades the new content in. `HomeWindowController.showWindow` and `EditorWindowController.init` both take the window, so going Home closes the project, and opening a project (from Home, the Finder or File > Open) replaces the one open. Closing the window quits (`applicationShouldTerminateAfterLastWindowClosed`). The canvas stops its playback clock when it leaves the window. The test kit's log shows `window=` (Home or Editor), `wins=` and `docs=`, with `home` and `openfile` steps; its script runs once, from the first project opened.
- **Home folders**: real folders one level down in the creations folder. `Library` lists `folders` and every project (`Item.folder`, nil when loose); `selectedFolder` (nil for All Projects) picks `shownItems`. The home screen is laid out as re-Flip's (`re-Flip/Sources/Flip/UI/HomeView.swift` has the measurements): plain 32 pt sidebar rows with no icons, a dim New Folder row under the folders that becomes a name field, 158 pt cards with the thumbnail as wide as the card (148 pt) at its own height, at most square, with its own rounded corners and no ground behind it (the user asked for no side bands), a panel-coloured fill only under the pointer, and the date without the time. `move(_:to:)` moves a package (numbering a clashing name), `newFolder(named:)`, `rename(_ folder:)`, `moveToTrash(_ folder:)`. Cards are `.draggable(url)` and sidebar rows `.dropDestination(for: URL.self)`; the card menu's Move to lists folders (our menus have no submenus, so a header and items). `Creations.folder` honours `TWINE_CREATIONS`, which the test kit sets to its own folder, so the test copy never touches the user's projects. Posted right-clicks miss our right-click menus over SwiftUI (they check `NSApp.currentEvent`), and the background test copy swallows a first queued one, so card and folder menus and drags are for a real mouse; the kit's `moveproject`/`showfolder` steps drive the library directly.
- **The window chrome**: `ChromelessWindow` (in `Components/Floating.swift`). The traffic lights are moved by hand to 20pt in, and `TrafficLights.keepPlaced` puts them back after AppKit re-lays out the title bar (it does on every title or edited-state change in a document window). Corrections run a turn later, once per burst, and give up after three misses: correcting synchronously from the frame notification recursed until the app crashed. Do not add a toolbar to lower them instead: a taller title bar makes SwiftUI stretch scroll views up under it, which misaligned clicks in the inspector.
- **Focus**: no field has the keyboard when a window opens, and `ChromelessWindow.sendEvent` ends a text edit when a click lands anywhere outside the field.
- **Saving**: autosave in place, plus a save one second after changes stop (`ProjectDocument.scheduleSaveSoon`). `NSDocument`'s read and save overrides are `nonisolated` and step onto the main actor; the package `FileWrapper` is kept and reused so media is never rewritten.
- **Menus** are the app's own (`Components/Menus.swift`), drawn on the panel card. One `MenuHost` per window.
- **Canvas**: `CanvasNSView` owns a `CoreAnimationRenderer` whose root sits in a `world` layer scaled and moved for zoom and pan; the selection is drawn by `CanvasOverlay` in view points. It renders from `show(...)`, which `updateNSView` calls, and never writes to the model there. A plain drag on a layer always moves it; moving the anchor needs Command, because the anchor sits where moves start. Option-drag in Design duplicates first (`EditorController.duplicateForDrag`, inside the drag's continuous change, so one undo) and drags the copies; a press that never moves cancels. Resizing a group changes its scale, not its size; resizing a frame changes its size. A click picks the outermost group (`inContext` in `layer(at:deep:)`) unless the selection is already inside one: then it picks the selected layer, a sibling of it, or what holds it, as Figma does; a double-click goes one level in.
- **Colour picking** is the app's own `ColorPicker` (saturation square, hue and alpha bars, eyedropper, hex) on a `PopupCard`, raised by `ColorWell` through `MenuHost.showPopup`. No third-party code: Flip vendors a library for this; Twine does not.
- **Playback**: the canvas owns a `CADisplayLink` only while playing and calls `EditorController.advance(by:)`. The canvas and timeline representables read `editor.time` inside `updateNSView`, so a new playhead time updates them without re-running the whole window's SwiftUI. Bare keys (M, Space, comma and full stop with Shift or Option, Home, End) live in `EditorKeys`, handled by the canvas and the timeline, never as menu keys, so a letter typed in a field stays a letter.
- **Modes never share a control.** `EditorController.setMode` switches (and M does, through `EditorKeys`, never a menu key). Design: the canvas shows `evaluateDesign`, the inspector is `designContent` (layer, several layers, composition), handles and tools work, playback keys are off. Animate: the canvas shows `evaluate(at: time)`, only selects and moves (a move changes the design position), and the inspector is `AnimationInspector` (Add Action, which uses `ActionFactory` for defaults at the playhead, and the selection's actions). `EditorController.scene` follows the mode.
- **Editing actions**: `ActionInspector` shows the selected actions' fields (`TimingFields`, `EasingFields` with the custom `CurveEditor`, `ValueFields`); edits go through `EditorController.editActions` (one undo step) or `updateActions` (inside begin/end). `OptionalField` is a number that may be empty, showing the inherited value as a placeholder. `ActionGeometry` (MotionEditing, tested) turns points, sizes and angles into what an action stores, and switches To/By without changing the motion. `EditorController.canvasAction` is the one action the canvas edits: a Move shows its path (`CanvasOverlay.Motion`) with draggable ends and curve handles; dragging the layer sets the end from where it rests; the start dot over the layer needs Command. Resize, Scale and Rotate draw their outline and handles at the action's end state (`actionEndBox`) and seek there on grab. `layerUpdate` makes any design position change carry the layer's Move actions' absolute positions along.
- **Style and Blur actions** (Colour, Stroke, Trim, Corner Radius, Shadow, Layer Blur, Background Blur) are channels like any other in `ActionTracks`, with `LayerState` fields that are optional where a layer may not have the thing (`fill`, `stroke`, `trim`, `cornerRadii`); `resolve` in `Evaluate.swift` writes the state back onto the first fill, first stroke, rectangle corners and first switched-on shadow and blurs. Shadow and blurs start from `DropShadow.noShadow` / `BackgroundBlur.noBlur` / 0 when the design has none (never name these `none`: `.none` on an optional silently means nil). Paint blending (`Interpolation.swift`) pairs gradient stops when counts match and resamples at every stop position when they do not; a shadow with no opacity takes the other side's colour. `ActionFactory.kinds(for:)` decides what the menu offers; the menu groups by `ActionKind.category`. Inspector fields are `StyleValueFields`, with `PaintControls`, `ShadowControls` and `PaintSwatch` in `Components/PaintControls.swift`.
- **Text** is set by `TextLayout` in MotionEvaluation, used for measuring (evaluation, the store) and drawing (`MotionRendering/TextImage.swift`), so the box always matches the ink. Lines are placed by hand, one line height each with the glyphs centred in it (Figma's half-leading). A text box's size is always its words' size: `EditorCommand.apply` refits every text layer after every command (`Layer.fittedText`), and `resolve` measures at every frame, moving the anchor by alignment (`TextLayout.anchor`). Text is drawn as an image per text (two during a Counter or Change Text swap, `ShownText`/`TextSwap`), cached by `TextImage.Key`. Pictures come out upside down off screen, so `CoreAnimationRenderer.flipsContents` (set by `OffscreenRenderer`) turns them over; `textIsTheRightWayUp` guards it. Text is typed on the canvas (`Canvas/CanvasTextEditing.swift`): `CanvasNSView` conforms to `NSTextInputClient` and keeps a `TextSession` (an `EditableText` from MotionEditing, with its own undo history); `TextGeometry` (MotionEvaluation) gives caret, hit and selection boxes from the same layout that draws the text, transformed into view points for `CanvasOverlay.updateText`. The session is one continuous change (one undo step); `responds(to:)` claims Copy, Cut, Paste, Select All, Delete, Undo and Redo only while typing, so otherwise they reach the window controller. `EditorModel.editingText` names the layer being typed into. The inspector's text box also edits the words. Counter and Change Text share the `text` channel; `ActionTracks.shownText` is its walk.
- **Arc and Star** live in the geometry: `.ellipse(arc: EllipseArc)` and `.star(points:innerRadius:cornerRadius:)`, both decoding older files with defaults. `ShapePaths.rounded` rounds any straight-sided path.
- **Media**: `ProjectDocument` copies imports aside (`stage`, `stagedMedia`) and adds them to the package's `media` folder on save; `mediaURL(for:)` finds a file there or in the saved package. `MediaImport` probes and fingerprints files; `EditorController.importMedia` makes the layers (pictures as picture-filled rectangles) and Play actions (File > Import, and drops on `CanvasNSView`). A Play is an ordinary action (`.play(PlayAction(trimStart:))`) on the `media` channel: `ActionTracks.sourceTime` gives the frame (first before, last after), and `ActionEditing.trimmed` moves `trimStart` with the start edge and stops at the file's ends. `MediaLibrary`/`VideoFrames` (MotionRendering) decode frames in order with AVAssetReader, restarting only on a jump, for the canvas and export alike; decoded video is taken as sRGB whatever it is tagged, as exports write it. Pictures are converted to sRGB on load. `audioClips(project)` (MotionEvaluation) is the sound, which `AudioComposition` lays out for AVFoundation: `AudioPreview` plays it following the playhead (started with `setRate(_:time:atHostTime:)` a moment ahead on the host clock the display link runs on, once the player is ready; small drift is judged only after a settle, jumps at once, and nothing past where the sound runs out, where the player has stopped by itself: it used to be sought every frame there, and on later loops only nudged along, never playing, which was the stutter), `AudioMixdown` writes it (AAC in MP4, 16-bit PCM in MOV). The timeline draws waveforms from `Waveforms`, normalised to each file's loudest peak, and shaped by the layer's Volume actions. A Volume action (`VolumeAction`, 0 to 1, the `volume` channel, `LayerState.volume` starting from the design volume) becomes each clip's `envelope` of `VolumePoint`s (`volumeEnvelope`: a point just before and at each start, about thirty a second through each fade, so straight lines follow the easing), which `AudioComposition` turns into `setVolumeRamp`s, so preview and export hear the same fades. Volume and the sound presets are only offered where `Project.hasSound(_:)` (a sound, or a video whose asset `hasAudio`): use `ActionFactory.kinds(for:in:)` and `Presets.available(for:in:)`, which know the media; the plain `kinds(for:)` takes `hasSound`. The Design Sound section hides for a video without sound. Volume stops at 100% everywhere (the Design slider and the action, as the user asked); older projects saved above it are heard at 100% (`min` in `LayerState(design:)` and `audioClips`).
- **Snapping and alignment**: the maths is `MotionEditing/Snapping.swift` (tested): `Snapping.move` (edges, centres, even spacing among boxes overlapping across the axis) and `Snapping.point` (a drawn corner or a resize handle), returning an offset plus `Guide`s and `Gap`s in composition space; `Alignment.align` and `.distribute` give per-layer moves. Everything works on upright boxes from `ResolvedScene.bounds(of:)` (a group's box is what is drawn inside it). The canvas gathers `snapTargets` when a drag begins, snaps in `mouseDragged` (not with ⌘, not when `EditorModel.snaps` is off, resize only when the layer sits upright and Shift is not held), and draws the result with `CanvasOverlay.updateSnap` in `Theme.guide`. Align and distribute are `EditorController.align`/`distribute`, Design only; their keys are `AlignKeys` on the canvas (by key code), named in the Arrange menu's titles, never menu keys, so Option-letter still types accents.
- **Presets** (`MotionEditing/Presets.swift`, tested): a `Preset` is Codable data, a list of `PresetStep`s (start offset, duration, easing, `PresetEffect`), with effects measured from the layer's state at the playhead ("own"). `Presets.actions` turns one into ordinary actions; nothing of the preset is kept. A new preset is a new value in `Presets.library`; only a new kind of effect needs code. `EditorController.addPreset` and `addAction` share `insertAndShow` (bottom rows, select, reveal, glide to the end).
- **Masks**: `Layer.mask` (a `MaskReference`) names another layer; `Project.maskCandidates(for:)` lists the allowed ones (anything that draws, not the layer's own groups). `evaluate` leaves mask layers out of `ResolvedScene.layers` and puts them in `ResolvedScene.masks` (found by `layer(_:)` too, so a selected mask gets its box), ignoring solo; each masked layer's `ResolvedMask.transform` carries the mask's space into its own, through any groups (`WorldTransforms`). A switched-off or hidden mask gives `mask == nil`: the layer shows whole. The renderer draws each mask with a `MaskNode` of its own set as the masked container's `mask`; inverted, an opaque sheet with the mask punched out by the private `destOut` compositing filter (`Compositing` in `Blur.swift`). Canvas hit testing honours masks, and picks a mask only while it is selected.
- **Blur** is in Figma's units everywhere in the model: twice the Gaussian's standard deviation (CSS's shadow blur). The renderer halves it for Core Animation. `MotionRendering/Blur.swift` uses Core Animation's private `CAFilter` `gaussianBlur` and `CABackdropLayer`, looked up by name, because `CIGaussianBlur` draws about 9 px off (at radius 12) on screen and off, and `backgroundFilters` only see siblings, not what is behind a nested layer. If either class is missing, layer blur falls back to Core Image and background blur is skipped. Setting the filter's `inputNormalizeEdges` makes it draw nothing in `CARenderer`. The backdrop sits under a shape's paint layers, masked to its path, with opacity as the blend.
- **Export**: `Exporter.export` blocks, so `ExportSession` (one per window, on `EditorModel.exports`) runs it on a background queue from a copy of the project, with settings saved to `UserDefaults`. The inspector's `PrimaryButton` (at its foot, both modes) and ⌘E call `EditorController.openExport`, which raises `ExportPanel` (`EditorModel.showExport`) over the whole window: settings on the left; on the right an `ExportPreview` (its own `CoreAnimationRenderer`, sharing the canvas's `MediaLibrary`) driven by an `ExportPreviewPlayer` (its own display link, playhead snapped to the export's frames, its own `AudioPreview`), which rises out as the `StepCounter` comes up (`Theme.exportEase`, cubic-bezier(0.5, 0, 0, 1); each changed digit steps up once, old out the top and new in from below, keyed by `.id(digit)`, in a window sized from `ThemeFont.displayFigures` and feathered at its edges; the user found an odometer's rolling too busy). `ExportKeys` makes the canvas and timeline swallow keys while it is up (Escape closes, Space plays). `closeExport` cancels an export in flight and forgets `ExportSession.completed` (the file Export Again and Show in Finder refer to). Quality is forced to High in `ExportSession.begin`, as the user asked. `ExportSettings.frameRate` (nil for the composition's) is applied by `Exporter.export` through `exported(_:)`, and a range's frames are counted at that rate. `ExportStatus`, the small card at the top, now only shows for exports made outside the panel (Export Current Frame). The panel's Export button calls `ExportSession.request`, which the window controller sets, rather than sending an action through the responder chain, which misses when the window is not key. Files are written in a replacement folder and moved into place when complete. Formats without alpha export over the background colour; formats with alpha store straight (unpremultiplied) colour, unpremultiplied with vImage, since ProRes specifies it and editing apps and ffmpeg expect it. Colour is tagged Rec. 709. A PNG in Design mode is the design (`actions` emptied), otherwise the frame at the playhead. Check exports with `ffprobe` and `ffmpeg` (in `/opt/homebrew/bin`) rather than only AVFoundation, which agrees with itself. `ExportSettings.scale` is any multiple (the size menu offers 0.5, 1, 2 and Custom…, which shows a Scale field taking a percentage), held by `effectiveScale` to 4K (`maxLongSide` 3840, `maxShortSide` 2160, either way round); `pixelSize` is the only place sizes are worked out, rounding movies to even pixels, which cannot pass 4K as its sides are even. A range (`ExportSession.range`, per window, unsaved) becomes `frames` for `Exporter.export`: `ExportTiming` starts the movie at zero from `firstFrame`, and `AudioMixdown` reads from the range's start and shifts each sample back by it.
- **Timeline**: full width along the bottom in Animate (`EditorView`), height in `UserDefaults` (`EditorModel.timelineHeight`). `TimelineRow.rows` is one flat row per action in `ActionEditing.timeline` order: `rowOrder` is global across the project, a new action takes `ActionFactory.nextRowOrder(in:)` (the bottom), and dragging a label or bar renumbers with `ActionEditing.moving`. Continuous updates build on the current state, so a drag sends every row that differs from now, worked out from the rows as they are that moment (not the drawn ones). The header is the transport over `TimelineRow.labelWidth` (equal to `Theme.panelWidth`, so it lines up with the layers panel) and the ruler (`TimelineRulerView`: whole seconds with dots, the teal `Theme.playhead` pill with the time, the scene end to drag); the tracks (`TimelineTracksView`, an AppKit view in its own `NSScrollView`) draw labels (layer, action; the hovered label gets `Theme.rowHover` and its eye) in that column, with handles at the ends of the hovered bar marking the trim zones (`trimEdge`, reaching `edgeReach` in on long bars) and share `TimelineViewport` with the ruler, whose `start` never goes earlier than 0s less `TimelineViewport.lead`. Stagger, Show Only Selected Layers and Show Times as Frames are on the right-click menu. Clicks on the ruler or empty timeline call `EditorController.glide(to:)` (a short eased slide on a timer, cancelled by any `seek`, scrub or play); drags call `seek`. `EditorModel.revealActions` (ids plus a request count, so the view never writes back) asks the tracks to scroll new rows into view; `addAction` sets it. Timing, trimming, reordering, stagger, duplicate and paste maths live in `MotionEditing/ActionEditing.swift` with tests. `editor.selectedActions` holds picked actions; `EditorController.selectedActions` only returns those whose layer is still selected. `timelineHasFocus` (Animate and the timeline clicked last) decides whether Delete, Copy, Paste and Duplicate act on actions or layers.

## Performance

Performance is one of the most important parts of the tool. Measure before and after any change to evaluation, rendering, the canvas, the timeline or the panels:

```bash
cd Packages/MotionKit && TWINE_BENCH=1 swift test -c release --filter PerformanceTests
```

That prints per-frame timings for a 200-layer, 990-action scene (`stressProject` in `Tests/MotionRenderingTests/PerformanceTests.swift`; `TWINE_BENCH_OUT=path` writes it as a document to open in the app). In September 2026, release build: evaluate 1.2 ms, still layout 0.4 ms, layer tree update 0.34 ms (0.30 before blend modes and path shadows), a 1080p offscreen frame 11.4 ms (14.6 before); in the app, playback 60 fps, a canvas drag step 6 to 8 ms, a timeline bar drag step 9 ms, a scrub step 4 ms, selecting a layer about 27 ms (SwiftUI building the inspector). Profile the running test copy with `sample <pid> 5` and read the main thread's call tree.

What keeps it fast, and must stay so: `TextLayout` caches fonts and laid-out lines behind a `Mutex` (text is the dearest thing in a frame); `ResolvedScene` looks layers up through an index built once in `init`, so its lists are `let`; `CoreAnimationRenderer`'s `Node` skips a layer whose `ResolvedLayer` is unchanged (pictures and video always refresh); the timeline sorts small keys, not whole actions; ids compare by bytes (`UUID.precedes`), never by `uuidString`. Never do per-row or per-layer work that scans the whole project (the layers panel once checked every layer for masks in every row). After changing a stored property of a struct in MotionKit, run `swift package clean` (and delete `build/DerivedData` for the app): an incremental build can keep the old layout and crash in ways that look like real bugs.

## Cursors

`Twine/Components/Cursors.swift` loads the designer's 32 by 32 SVGs from `Twine/Resources/Cursors` (copied from the supplied set in `~/Desktop/26-09/Cursor`; the brush one is unused) as `NSCursor`s, falling back to system cursors. `Cursors.arrow` replaces the system arrow everywhere: `Cursors.useAppArrowEverywhere()` (called first thing at launch) swaps `+[NSCursor arrowCursor]` for it with `method_exchangeImplementations`, because SwiftUI's hosting views set the arrow on every mouse move and cursor rects cannot overrule them. `CursorArea` and the timeline's base cursor rects use it too. Write `Cursors.arrow`, not `NSCursor.arrow`, so the intent reads plainly. SwiftUI puts its arrow back over cursor rects as the pointer moves, so AppKit views set their pointers on `mouseMoved` and `cursorUpdate` too (the ruler: `TimelineRulerView.cursor(at:)`, with the whole ruler taking the held pointer while its pill or the scene end is dragged), and SwiftUI views use `.pointerStyle(.image(...))` (the timeline's top edge). The pen has four (`pen`, `penAdd` over a segment, `penMove` over a point, `penConnect` over an end it can join), set on `mouseMoved` by `pathMouseMoved`, hot spot at the nib. `Cursors.resize(toward:)` and `.rotate(toward:)` pick by the handle's or corner's direction on screen, so turned layers get the right arrows. Hover is shared: `EditorModel.hoveredLayer` is set by the canvas (`setHover`, which only clears its own) and by layers panel rows, and both draw it: the canvas as a white line on a dark edge, with no wash inside (the user asked for the outline alone) (`Theme.canvasHover`, `.canvasHoverEdge`; a grey version vanished on grey layers), nothing on a selected layer (the user wants only the selection box there), the row as its full hover state (`LayerRow.lit`, switches included).
