# eMotion: notes for working on it

The original brief is `docs/brief.md`. The project is now working through a Jitter-style redesign: `docs/redesign.md` (the brief) and `docs/redesign-decisions.md` (answers, which win where they differ). Read both before a milestone. This file is the map and the rules.

## Rules

- **No em dashes anywhere**: UI strings, comments, docs, commit messages.
- No third-party dependencies without asking.
- Every milestone ends with: `./make-app.sh` with no warnings, `./test.sh` passing, a new entry at the top of `eMotion/VersionHistory.swift`, a commit, and a push to `inbox-nidhinm/eMotion`.
- The user is a designer, not an engineer. Explain in plain terms.
- No help text in the UI. States are shown, not explained. Put explanations in `.help()` tooltips.
- Views never write literals: every colour, size and radius comes from `Theme` (in `Packages/MotionKit/Sources/Theme`). Values come from the "Flip Design System" page of Figma file `2XErpBfGuIGNU0DkL58Ute` (node 171:2055), with a light blue accent (#4C9FEF) in place of Flip's green.
- **Accessibility presses do not prove clicks work.** They skip hit testing. To test real clicks without touching the user's mouse, post `NSEvent` mouse and key events through `window.sendEvent` from a temporary in-app hook, and log state after each. After each step post an `.applicationDefined` event through `NSApp.postEvent`: events sent straight to a window skip the event loop, so the undo group never closes, the document never counts as edited, and nothing saves. Remove the hook before committing.
- **Posted events do not reliably reach SwiftUI gestures.** `onTapGesture` and `DragGesture` sometimes ignore events sent through `window.sendEvent` for a whole session, while real `Button`s always respond. Make clickable controls real buttons; for drags in SwiftUI views (the curve editor), set the value from the hook and say the drag itself was not exercised.
- **The save panel runs in another process.** A test hook can fill it in (`directoryURL` is ignored once it is up; set `NSNavLastRootDirectory` in the test copy's defaults instead) and close it with `window.endSheet(panel, returnCode: .OK)`; `panel.ok(nil)` throws. Errors are presented as sheets on the window (`presentError(_:modalFor:...)`) so they show in window captures.
- **Never drive the copy of the app the user is using.** For scripted tests make a copy of `build/eMotion.app` with its own bundle id (`com.nidhin.emotion.selftest`) and point it at a throwaway project in the scratchpad.
- When driving the running app to verify, the user is often working in other apps. Launch with `open -g`, use accessibility presses (`click button N of ...`) rather than synthetic keys or clicks, and never type unless eMotion is frontmost. Setting a SwiftUI text field's value through accessibility does not reach its binding.

## Layers of the code

| Where | What | May import |
|---|---|---|
| `Packages/MotionKit/Sources/MotionModel` | The document: plain `Codable`, `Sendable` value types. File format and migrations in `FileFormat.swift`. | Foundation |
| `Packages/MotionKit/Sources/MotionEditing` | `EditorCommand` (every allowed change, including actions), `ProjectStore` (applies commands, snapshot undo, continuous changes), `Arrangement` (group, ungroup, restack, carrying actions along), `LayerFactory`, `LayerEditing` | Foundation, MotionModel, MotionEvaluation |
| `Packages/MotionKit/Sources/MotionEvaluation` | `evaluate(project, at:)`, `evaluateDesign(project)` and `ResolvedScene`: `ActionTracks` (the action rules), easing presets, springs, OKLab blending, shape paths, `Affine`, `TextLayout` (Core Text: fonts, fallback, line placement, measuring), `NumberFormat` (counters) | Foundation, CoreText, MotionModel |
| `Packages/MotionKit/Sources/MotionRendering` | `SceneRenderer`, `CoreAnimationRenderer`, `OffscreenRenderer` (CARenderer into Metal, for thumbnails, stills and every exported frame), `MediaLibrary` (pictures and video frames) | QuartzCore, Metal, AVFoundation |
| `Packages/MotionKit/Sources/MotionExport` | `ExportSettings` (format, scale, quality, audio), `ExportTiming` (frame times as exact fractions), `Exporter` (AVAssetWriter movies and PNG stills), `AudioComposition`/`AudioMixdown` (sound), `ExportJob` (cancel) | AVFoundation, VideoToolbox, ImageIO, Accelerate |
| `Packages/MotionKit/Sources/Theme` | Tokens, type, grain, icons (`Icons.swift` is generated) | SwiftUI |
| `eMotion/` | The app: AppKit lifecycle, `NSDocument`, SwiftUI views | everything |

In the app, `Editor/EditorController.swift` is where every canvas gesture, menu item and inspector edit becomes a command, and `Canvas/` holds the AppKit canvas, its drag maths and its overlay.

## Decisions worth knowing

- **Undo is by snapshot.** `ProjectStore` records the whole `Project` before each command. Drags and sliders use `beginContinuousChange` / `updateContinuousChange` / `endContinuousChange` so they undo as one step.
- **Layers are stored back to front** (last in the array is in front). The layers panel shows them reversed.
- **Coordinates are Figma's**: origin top-left, y down, rotation clockwise in degrees. Anchor is in pixels from the layer's top-left. Scale 1 is 100%, opacity 0 to 1.
- **Actions, not keyframes.** A layer's properties are plain values: its design state. `Project.actions` is a flat list; each `Action` targets one layer, has a start, a duration (0 is instant), an easing, and an `ActionSpec` carrying its own typed optional initial value and end value. Layers have no in or out points.
- **The action rules live in one place**: `walk` in `MotionEvaluation/ActionTracks.swift`, with its numbered comment. Each action drives one channel (position, scale, rotation, opacity, size, visibility). On one channel of one layer, actions go in start order (ties by `rowOrder`); an empty initial value inherits the value at the action's start; the first action's explicit initial value holds from time 0 (entrances); a later action takes over from the value at its own start. Channels never interfere. By mode adds (Scale By multiplies); To is absolute. Resize grows around the anchor. A first Show hides the layer until it.
- **Easing** is a named preset with an intensity (none, smooth, slow down, accelerate, overshoot, spring) or a custom bezier. Presets are worked out at evaluation, so improving one improves every action. A spring's motion is fitted to the action's duration.
- **Actions follow their layers**: `EditorCommand.apply` drops actions whose layer is gone, whatever command removed it. Grouping and ungrouping remap To values and initial values into the new parent space (`Action.remapped`); duplicating and pasting copy actions through `duplicated(recordingIDs:)` and `actionCopies(for:)`.
- **File format 2** is the first with actions. Anything older is refused with a plain message (`ProjectFileError.olderVersion`, whose `failureReason` is what the open alert shows).
- **Fills, strokes and effects are lists** so a future Figma import keeps everything. The MVP UI edits the first.
- **Paths are plain data** (`BezierPath`), for SVG import, boolean operations and morphing later.
- **The window chrome**: `ChromelessWindow` (in `Components/Floating.swift`). The traffic lights are moved by hand to 20pt in, and `TrafficLights.keepPlaced` puts them back after AppKit re-lays out the title bar (it does on every title or edited-state change in a document window). Corrections run a turn later, once per burst, and give up after three misses: correcting synchronously from the frame notification recursed until the app crashed. Do not add a toolbar to lower them instead: a taller title bar makes SwiftUI stretch scroll views up under it, which misaligned clicks in the inspector.
- **Focus**: no field has the keyboard when a window opens, and `ChromelessWindow.sendEvent` ends a text edit when a click lands anywhere outside the field.
- **Saving**: autosave in place, plus a save one second after changes stop (`ProjectDocument.scheduleSaveSoon`). `NSDocument`'s read and save overrides are `nonisolated` and step onto the main actor; the package `FileWrapper` is kept and reused so media is never rewritten.
- **Menus** are the app's own (`Components/Menus.swift`), drawn on the panel card. One `MenuHost` per window.
- **Canvas**: `CanvasNSView` owns a `CoreAnimationRenderer` whose root sits in a `world` layer scaled and moved for zoom and pan; the selection is drawn by `CanvasOverlay` in view points. It renders from `show(...)`, which `updateNSView` calls, and never writes to the model there. A plain drag on a layer always moves it; moving the anchor needs Command, because the anchor sits where moves start. Resizing a group changes its scale, not its size.
- **Colour picking** is the app's own `ColorPicker` (saturation square, hue and alpha bars, eyedropper, hex) on a `PopupCard`, raised by `ColorWell` through `MenuHost.showPopup`. No third-party code: Flip vendors a library for this; eMotion does not.
- **Playback**: the canvas owns a `CADisplayLink` only while playing and calls `EditorController.advance(by:)`. The canvas and timeline representables read `editor.time` inside `updateNSView`, so a new playhead time updates them without re-running the whole window's SwiftUI. Bare keys (M, Space, comma and full stop with Shift or Option, Home, End) live in `EditorKeys`, handled by the canvas and the timeline, never as menu keys, so a letter typed in a field stays a letter.
- **Modes never share a control.** `EditorController.setMode` switches (and M does, through `EditorKeys`, never a menu key). Design: the canvas shows `evaluateDesign`, the inspector is `designContent` (layer, several layers, composition), handles and tools work, playback keys are off. Animate: the canvas shows `evaluate(at: time)`, only selects and moves (a move changes the design position), and the inspector is `AnimationInspector` (Add Action, which uses `ActionFactory` for defaults at the playhead, and the selection's actions). `EditorController.scene` follows the mode.
- **Editing actions**: `ActionInspector` shows the selected actions' fields (`TimingFields`, `EasingFields` with the custom `CurveEditor`, `ValueFields`); edits go through `EditorController.editActions` (one undo step) or `updateActions` (inside begin/end). `OptionalField` is a number that may be empty, showing the inherited value as a placeholder. `ActionGeometry` (MotionEditing, tested) turns points, sizes and angles into what an action stores, and switches To/By without changing the motion. `EditorController.canvasAction` is the one action the canvas edits: a Move shows its path (`CanvasOverlay.Motion`) with draggable ends and curve handles; dragging the layer sets the end from where it rests; the start dot over the layer needs Command. Resize, Scale and Rotate draw their outline and handles at the action's end state (`actionEndBox`) and seek there on grab. `layerUpdate` makes any design position change carry the layer's Move actions' absolute positions along.
- **Style and Blur actions** (Colour, Stroke, Trim, Corner Radius, Shadow, Layer Blur, Background Blur) are channels like any other in `ActionTracks`, with `LayerState` fields that are optional where a layer may not have the thing (`fill`, `stroke`, `trim`, `cornerRadii`); `resolve` in `Evaluate.swift` writes the state back onto the first fill, first stroke, rectangle corners and first switched-on shadow and blurs. Shadow and blurs start from `DropShadow.noShadow` / `BackgroundBlur.noBlur` / 0 when the design has none (never name these `none`: `.none` on an optional silently means nil). Paint blending (`Interpolation.swift`) pairs gradient stops when counts match and resamples at every stop position when they do not; a shadow with no opacity takes the other side's colour. `ActionFactory.kinds(for:)` decides what the menu offers; the menu groups by `ActionKind.category`. Inspector fields are `StyleValueFields`, with `PaintControls`, `ShadowControls` and `PaintSwatch` in `Components/PaintControls.swift`.
- **Text** is set by `TextLayout` in MotionEvaluation, used for measuring (evaluation, the store) and drawing (`MotionRendering/TextImage.swift`), so the box always matches the ink. Lines are placed by hand, one line height each with the glyphs centred in it (Figma's half-leading). A text box's size is always its words' size: `EditorCommand.apply` refits every text layer after every command (`Layer.fittedText`), and `resolve` measures at every frame, moving the anchor by alignment (`TextLayout.anchor`). Text is drawn as an image per text (two during a Counter or Change Text swap, `ShownText`/`TextSwap`), cached by `TextImage.Key`. Pictures come out upside down off screen, so `CoreAnimationRenderer.flipsContents` (set by `OffscreenRenderer`) turns them over; `textIsTheRightWayUp` guards it. Text is typed on the canvas (`Canvas/CanvasTextEditing.swift`): `CanvasNSView` conforms to `NSTextInputClient` and keeps a `TextSession` (an `EditableText` from MotionEditing, with its own undo history); `TextGeometry` (MotionEvaluation) gives caret, hit and selection boxes from the same layout that draws the text, transformed into view points for `CanvasOverlay.updateText`. The session is one continuous change (one undo step); `responds(to:)` claims Copy, Cut, Paste, Select All, Delete, Undo and Redo only while typing, so otherwise they reach the window controller. `EditorModel.editingText` names the layer being typed into. The inspector's text box also edits the words. Counter and Change Text share the `text` channel; `ActionTracks.shownText` is its walk.
- **Arc and Star** live in the geometry: `.ellipse(arc: EllipseArc)` and `.star(points:innerRadius:cornerRadius:)`, both decoding older files with defaults. `ShapePaths.rounded` rounds any straight-sided path.
- **Media**: `ProjectDocument` copies imports aside (`stage`, `stagedMedia`) and adds them to the package's `media` folder on save; `mediaURL(for:)` finds a file there or in the saved package. `MediaImport` probes and fingerprints files; `EditorController.importMedia` makes the layers and Play actions (File > Import, and drops on `CanvasNSView`). A Play is an ordinary action (`.play(PlayAction(trimStart:))`) on the `media` channel: `ActionTracks.sourceTime` gives the frame (first before, last after), and `ActionEditing.trimmed` moves `trimStart` with the start edge and stops at the file's ends. `MediaLibrary`/`VideoFrames` (MotionRendering) decode frames in order with AVAssetReader, restarting only on a jump, for the canvas and export alike; decoded video is taken as sRGB whatever it is tagged, as exports write it. Pictures are converted to sRGB on load. `audioClips(project)` (MotionEvaluation) is the sound, which `AudioComposition` lays out for AVFoundation: `AudioPreview` plays it following the playhead, `AudioMixdown` writes it (AAC in MP4, 16-bit PCM in MOV). The timeline draws waveforms from `Waveforms`, normalised to each file's loudest peak.
- **Snapping and alignment**: the maths is `MotionEditing/Snapping.swift` (tested): `Snapping.move` (edges, centres, even spacing among boxes overlapping across the axis) and `Snapping.point` (a drawn corner or a resize handle), returning an offset plus `Guide`s and `Gap`s in composition space; `Alignment.align` and `.distribute` give per-layer moves. Everything works on upright boxes from `ResolvedScene.bounds(of:)` (a group's box is what is drawn inside it). The canvas gathers `snapTargets` when a drag begins, snaps in `mouseDragged` (not with ⌘, not when `EditorModel.snaps` is off, resize only when the layer sits upright and Shift is not held), and draws the result with `CanvasOverlay.updateSnap` in `Theme.guide`. Align and distribute are `EditorController.align`/`distribute`, Design only; their keys are `AlignKeys` on the canvas (by key code), named in the Arrange menu's titles, never menu keys, so Option-letter still types accents.
- **Masks**: `Layer.mask` (a `MaskReference`) names another layer; `Project.maskCandidates(for:)` lists the allowed ones (anything that draws, not the layer's own groups). `evaluate` leaves mask layers out of `ResolvedScene.layers` and puts them in `ResolvedScene.masks` (found by `layer(_:)` too, so a selected mask gets its box), ignoring solo; each masked layer's `ResolvedMask.transform` carries the mask's space into its own, through any groups (`WorldTransforms`). A switched-off or hidden mask gives `mask == nil`: the layer shows whole. The renderer draws each mask with a `MaskNode` of its own set as the masked container's `mask`; inverted, an opaque sheet with the mask punched out by the private `destOut` compositing filter (`Compositing` in `Blur.swift`). Canvas hit testing honours masks, and picks a mask only while it is selected.
- **Blur** is in Figma's units everywhere in the model: twice the Gaussian's standard deviation (CSS's shadow blur). The renderer halves it for Core Animation. `MotionRendering/Blur.swift` uses Core Animation's private `CAFilter` `gaussianBlur` and `CABackdropLayer`, looked up by name, because `CIGaussianBlur` draws about 9 px off (at radius 12) on screen and off, and `backgroundFilters` only see siblings, not what is behind a nested layer. If either class is missing, layer blur falls back to Core Image and background blur is skipped. Setting the filter's `inputNormalizeEdges` makes it draw nothing in `CARenderer`. The backdrop sits under a shape's paint layers, masked to its path, with opacity as the blend.
- **Export**: `Exporter.export` blocks, so `ExportSession` (one per window, on `EditorModel.exports`) runs it on a background queue from a copy of the project, with progress in `ExportStatus` at the top of the window and settings in `ExportSection` (Design, nothing selected) saved to `UserDefaults`. The Export button calls `ExportSession.request`, which the window controller sets, rather than sending an action through the responder chain, which misses when the window is not key. Files are written in a replacement folder and moved into place when complete. Formats without alpha export over the background colour; formats with alpha store straight (unpremultiplied) colour, unpremultiplied with vImage, since ProRes specifies it and editing apps and ffmpeg expect it. Colour is tagged Rec. 709. A PNG in Design mode is the design (`actions` emptied), otherwise the frame at the playhead. Check exports with `ffprobe` and `ffmpeg` (in `/opt/homebrew/bin`) rather than only AVFoundation, which agrees with itself. There is no audio yet: media layers come in redesign milestone 8, and audio is to be mixed in then.
- **Timeline**: full width along the bottom in Animate (`EditorView`), height in `UserDefaults` (`EditorModel.timelineHeight`). `TimelineRow.rows` is one flat row per action in `ActionEditing.timeline` order: `rowOrder` is global across the project, a new action takes `ActionFactory.nextRowOrder(in:)` (the bottom), and dragging a label or bar renumbers with `ActionEditing.moving`. Continuous updates build on the current state, so a drag sends every row that differs from now, worked out from the rows as they are that moment (not the drawn ones). The header is the transport over `TimelineRow.labelWidth` (equal to `Theme.panelWidth`, so it lines up with the layers panel) and the ruler (`TimelineRulerView`: whole seconds with dots, the teal `Theme.playhead` pill with the time, the scene end to drag); the tracks (`TimelineTracksView`, an AppKit view in its own `NSScrollView`) draw labels (layer, action; the hovered label gets `Theme.rowHover` and its eye) in that column, with handles at the ends of the hovered bar marking the trim zones (`trimEdge`, reaching `edgeReach` in on long bars) and share `TimelineViewport` with the ruler, whose `start` never goes earlier than 0s less `TimelineViewport.lead`. Stagger, Show Only Selected Layers and Show Times as Frames are on the right-click menu. Timing, trimming, reordering, stagger, duplicate and paste maths live in `MotionEditing/ActionEditing.swift` with tests. `editor.selectedActions` holds picked actions; `EditorController.selectedActions` only returns those whose layer is still selected. `timelineHasFocus` (Animate and the timeline clicked last) decides whether Delete, Copy, Paste and Duplicate act on actions or layers.
