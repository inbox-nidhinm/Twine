# Windows, Home and saving

Decisions worth knowing about windows, Home and saving, moved out of `CLAUDE.md` on 28 October 2026 so they load only when needed. Keep each entry up to date when its code changes.

- **The window's size** (5 October 2026): `MainWindow.present` gives every SwiftUI host no `sizingOptions` (the home screen grew the window with every folder) and sets `ChromelessWindow.sizeFloor` to `MainWindow.minimum` (1200 by 760, both screens), which its `minSize` and `contentMinSize` setters never go below: SwiftUI's hosts reset the window's smallest to zero when their content goes in, whatever their options, so windows could be dragged to half the width. A window saved smaller grows to it. The kit's `window` step logs both.
- **One window** (`App/MainWindow.swift`): the app has a single `ChromelessWindow`, kept for its whole life (`isReleasedWhenClosed` false, frame saved as "Main"), showing Home or one project's editor. It is handed between window controllers, since each `NSDocument` wants its own: `MainWindow.take(then:)` frees it from whoever has it (an `EditorWindowController` `leave`s: stops playback, menus and export, drops the window, removes itself from its document and calls `ProjectDocument.closeAfterSaving`, which autosaves first because closing a document directly would not), and `present(_:in:)` fades the new content in. `HomeWindowController.showWindow` and `EditorWindowController.init` both take the window, so going Home closes the project, and opening a project (from Home, the Finder or File > Open) replaces the one open. Closing the window quits (`applicationShouldTerminateAfterLastWindowClosed`). The canvas stops its playback clock when it leaves the window. The test kit's log shows `window=` (Home or Editor), `wins=` and `docs=`, with `home` and `openfile` steps; its script runs once, from the first project opened.
- **Home folders**: real folders one level down in the creations folder. The sidebar's rows (All Projects, the folders, New Folder) scroll when they do not fit, a divider and then Settings pinned at the foot (5 October 2026: every folder made the window grow). `Library` lists `folders` and every project (`Item.folder`, nil when loose); `selectedFolder` (nil for All Projects) picks `shownItems`. The home screen is laid out as re-Flip's (`re-Flip/Sources/Flip/UI/HomeView.swift` has the measurements): plain 32 pt sidebar rows with no icons, a dim New Folder row under the folders that becomes a name field, 158 pt cards with the thumbnail as wide as the card (148 pt) at its own height, at most square, with its own rounded corners and no ground behind it (the user asked for no side bands), a panel-coloured fill only under the pointer, and the date without the time. New Project (the button, or ⌘N while no project is open, `DocumentController.newDocument`) makes the project in `selectedFolder` (30 September 2026). A card's Info item raises `ProjectInfoCard` (`Library.info`): `ProjectDetails`, worked out on a worker thread from the open document's project or the saved file, gives the dates, size on disk and `Project.stats` (`ProjectStats`, MotionModel, tested: layers by kind through groups and frames, actions, presets, switched off, scenes, where the last action ends); the kit's `info NAME` step raises it. `move(_:to:)` moves a package (numbering a clashing name), `newFolder(named:)`, `rename(_ folder:)`, `moveToTrash(_ folder:)`. Cards are `.draggable(url)` and sidebar rows `.dropDestination(for: URL.self)`; the card menu's Move to lists folders (our menus have no submenus, so a header and items). `Creations.folder` honours `TWINE_CREATIONS`, which the test kit sets to its own folder, so the test copy never touches the user's projects; otherwise it is the folder chosen in the onboarding (`creationsFolder` in defaults, a plain path, set by `Creations.setFolder`/`chooseFolder`), or `Creations.defaultFolder` (`~/Documents/Twine Creations`, which `FormerName` uses). Posted right-clicks miss our right-click menus over SwiftUI (they check `NSApp.currentEvent`), and the background test copy swallows a first queued one, so card and folder menus and drags are for a real mouse; the kit's `moveproject`/`showfolder` steps drive the library directly.
- **Search** (⌘K, File > Search…, the user's request on 5 October 2026): `SearchCard` (`Components/SearchCard.swift`) over the window, raised by `showSearch(_:)` on `EditorWindowController` and `HomeWindowController` (one selector; `EditorModel.search` and `Library.search` hold the `SearchSource` while it is up). What it offers is gathered as it opens, while the canvas still has the keyboard: `EditorController.searchSource()` (`Editor/EditorSearch.swift`: actions and presets the selection takes, both ways of a pair by name through `Presets.suits`, tools, the timeline's right-click commands, layers and scenes only once something is typed, and typed values) and `Library.searchSource()` (`Home/HomeSearch.swift`: projects, the latest six with nothing typed, Tab for their card menu's items, a name step for Rename and New Folder; folders; Settings). Both add `MainMenu.searchSections`: every menu item `NSMenu.update()` enables at that moment, named as the menu names it (keys written in titles become the shortcut), run by sending its action once the card has gone and the keyboard is back with `preferredResponder`. Matching and typed values are `SearchMatch` and `TypedEntry` (MotionEditing, `CommandSearchTests`): `opacity 50`, `w 400`, `rot 45`, `length 6s`, `2.5s`, `f120`; values set the design through `layerUpdate` (in Animate `animatedUpdate`), as one undo step. Recent is per window kind in defaults (`SearchRecents`). The kit's `call search` opens it; menu commands are not listed in the test copy, whose window is never key, so they were checked only by reading.
- **Settings** (`Home/SettingsPage.swift`, the user's request on 1 October 2026, laid out as re-Flip's Settings page): the home sidebar's last row is Settings (where Version History was), which `Library.showsSettings` puts in the shelf's place; picking any folder row leaves it (`selectedFolder`'s `didSet`), and its foot has the Version History button and `Build N · vX`. Each kind is a card (the user's request, after Granola's settings): its name above, a `floatingPanel(shadow: false)` (flat on the page, 2 October 2026) holding rows of an icon tile, a name and the control at the right, parted by dashed lines (`Theme.settingsDash`), laid out by `Masonry` (a `Layout`: as many columns of at least `Theme.settingsCardMin` as fit, two to three, each card under the shortest column; it is asked at endless widths too, which once crashed it turning infinity into a column count). Explanations stay in tooltips, not second lines. Values live in `AppSettings.shared` (`App/AppSettings.swift`, `@MainActor @Observable`, each kept in defaults as it changes; the projects folder stays `Creations`'s own): `newProject` (a whole `Composition`, which `Creations.makeProject` writes), `nudge`/`shiftNudge` (the canvas's arrow keys, and the shortcuts card's line, so `ShortcutsCard.columns` is worked out each time), `actionEasing`/`actionDuration` (passed to `ActionFactory.make(duration:easing:)` by `addAction`; presets, Show and Hide, counters, sound fades and Play keep their own), `showsFrames` (what `EditorModel.showsFrames` starts from and writes back), `playsSound` (`AudioPreview.follow` mutes the player, kept in step), `exportFolder` (nil asks; set, `ExportSession.begin` writes there under a free numbered name, skipping the panel) and `revealsExports`. Only the home screen shows Settings, and the app has one window, so no open editor needs telling of a change.
- **Onboarding** (`Twine/Onboarding/Onboarding.swift`, the user's request on 29 September 2026, laid out as Flip's `re-Flip/Sources/Flip/UI/Onboarding.swift`): a 760 by 540 card (`Theme.onboardingCard`, the panel `onboardingPanel` wide down its left) over the app's grained ground, three pages turned like a leaf on a spine (`rotation3DEffect` to 90, the page changing edge-on): the introduction, the projects folder (the path is the button, `Creations.chooseFolder` as a sheet on the window) and five features (`OnboardingFeature`), each changing the sentence and the artwork. `OnboardingState.shared` holds whether it shows and its page: up on the first launch (`hasSeenOnboarding` in defaults, set however it is left), never by itself in the test copy (the kit's `onboarding` step raises it), and again from Help > Show Onboarding (`AppDelegate.showOnboarding`). `HomeView` and `EditorView` both draw it on top. While up it takes the keyboard through a local event monitor (Escape leaves, Return turns, Command keys still reach the menus); posted keys skip local monitors, so the kit cannot test Escape. Artwork is `OnboardingArt`: a looping silent video `onboarding-NAME.mp4` or `.mov` in `Twine/Resources`, else `.png` or `.jpg`, else a placeholder (names: `intro`, `folder`, and each feature's `rawValue`); the folder page writes the chosen folder's name over its artwork. The folder page's video plays once `OnboardingState.folderVideoWait` (1 s) after the page lands, and again each time a different folder is chosen (`folderPlays`, 3 October 2026), resting on its last frame between; turned back to, it stays there (`folderPageLanded`). The features change with a fade, not Flip's page curl, while the art is placeholders.
- **Opening card** (`Document/OpeningCard.swift`, the user's request, 1 October 2026): `DocumentController.openDocument(withContentsOf:...)`, which every way of opening goes through, shows "Opening NAME" with a loader ring in a borderless child window over the visible main window, then opens a turn later. Building the editor holds the main thread, so the card is drawn once and committed (`CATransaction.flush`) before the work, and its ring's turn and its fade in (after `OpeningCard.delay`, 0.3 s, so quick opens show nothing) are Core Animation animations, which run while the app is busy; it goes a turn after the open finishes. Posted steps cannot run while the main thread is held, so check it with `screencapture -l` on the test copy's windows (by its pid) mid-open, with a pause put in for the purpose.
- **The window chrome**: `ChromelessWindow` (in `Components/Floating.swift`). The traffic lights are moved by hand to 20pt in, and `TrafficLights.keepPlaced` puts them back after AppKit re-lays out the title bar (it does on every title or edited-state change in a document window). Corrections run a turn later, once per burst, and give up after three misses: correcting synchronously from the frame notification recursed until the app crashed. Do not add a toolbar to lower them instead: a taller title bar makes SwiftUI stretch scroll views up under it, which misaligned clicks in the inspector.
- **Focus**: no field has the keyboard when a window opens, and `ChromelessWindow.sendEvent` ends a text edit when a click lands anywhere outside the field.
- **Saving**: autosave in place, plus a save one second after changes stop (`ProjectDocument.scheduleSaveSoon`). `NSDocument`'s read and save overrides are `nonisolated` and step onto the main actor; the package `FileWrapper` is kept and reused so media is never rewritten. Files imported this session are not put in the wrapper (that copied every byte on the main thread, 3 s for an 844 MB video): `write(to:ofType:for:originalContentsURL:)` writes the package, then clones in (`copyItem`, instant on the same APFS volume) each file the project uses that it lacks, from its staged copy or the package before; the next save takes such a file into the wrapper from the saved package (`fileWrapper(ofType:)`), so it is linked across like the rest. A file found nowhere is left out with a notice. The staging folder is deleted on `close()`. `closeAfterSaving` keeps a project whose save fails open and asks on the window (Try Again, Close Without Saving; `askAfterFailedSave`); a locked file gets macOS's own Unlock or Duplicate first. After close, `ProjectDocument.isClosed` stops staging and saving, and `EditorController.closeDown` (from `leave` and `windowWillClose`) makes `perform`, `update` and `type` do nothing, so an import finishing late changes nothing, and stops WebM conversions (`WebMConversion.stopAll`, which also stops a conversion trying its second way). SVG and Figma reading run on a worker thread. The home screen reads a project's document again only when its save time changes (`Library.read`). Renaming the project in the layers panel's header shows the new name at once (`pendingName`) until `ProjectDocument.rename(to:done:)` reports the move, which takes a moment (seconds when it saves first). The test kit's `save` step logs how long it held the main thread.
- **Menus** are the app's own (`Components/Menus.swift`), drawn on the panel card. One `MenuHost` per window. A menu opened from inside a popup card goes over it and leaves it up (`show` keeps `popup`; `dismiss` then closes only the menu, `closeMenu`), since nothing outside a card can be clicked while it is up. A double-click on a layers panel row renames it (`editor.renaming`), read from `NSApp.currentEvent?.clickCount` in the row's one tap gesture, since a second, double tap gesture would hold back every single click; the test kit needs `dbl+qclick` for it. A layer's right-click menu is `EditorController.layerMenu(for:)`, whose Delete and Duplicate act on layers wherever the last click was (`deleteSelectedLayers`, `duplicateSelectedLayers`; through `deleteSelection` they went to the timeline's actions after a click there, 30 September 2026), and a click or right-click on a layers panel row sets `editor.focus` to `.canvas`; shown by the layers panel's rows and by `CanvasNSView.rightMouseDown` (Control-click too; it selects the layer under the pointer unless already selected, and over nothing deselects and offers Paste). Escape on the canvas closes an open menu first. ⌘⌫ is Ungroup (groups and frames), handled by the canvas's and timeline's `keyDown` rather than as a menu key, so it still deletes words in fields.
