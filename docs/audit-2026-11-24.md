# Audit of Twine, 24 November 2026

A read of the whole codebase at commit a90a4c4 (v0.2.55): about 55,000 lines of app and package code and 12,000 lines of tests. Six reviewers each read one area in full; the top findings of each were then checked against the code a second time. Nothing in the repo was changed.

How sure each finding is:

- **Confirmed**: every code path involved was read, and the top ones read twice. None was reproduced in the running app.
- **Plausible**: the code allows it, but the outcome depends on something only a real run can show (usually whether macOS delivers a mouse-up to a view that was removed mid-drag).

## Where it stands, 26 November 2026

Worked through from v0.2.56 to v0.2.66, each group built with no warnings, the unit tests passing (725 at the audit, 756 now) and pushed. Every finding below carries its status.

- Fixed: all of A (lost work), all of B (crashes), C1 to C5 and C7 to C9, most of C10, D1 to D3, D5, D6 and D8.
- Partly: C6 (a guard, the fault not reproduced), D4 and D7.
- Open: a handful of C10's smaller items and all of E (the project's own rules). None of these loses work or stops the app. F (housekeeping) was done in v0.2.69.
- Many fixes were tried in a separate test copy of the app, and some only by unit tests or by reading: the version history and the commit for each says which. What needs a real held mouse (keys during a drag, dragging layers in the panel, dropping files on the timeline) has not been exercised.

A usability review followed the audit (v0.2.61 to v0.2.63): thirty-odd small improvements, three changed decisions and four larger ones, all in the version history.


## What is in good shape

- The release build compiles with no warnings, and all 725 unit tests pass.
- No em dashes anywhere, in files or commit messages. The old name appears only where CLAUDE.md says it should.
- Every module imports only modules below it, as the layers table says. No third-party code.
- Colours, type and corner radii all come from Theme (one exception, below).
- Signing matches CLAUDE.md. No secrets or keys in the repo. No leftover test hook.
- The Figma plugin declares no network access and makes no requests.
- The AI connection is a private socket only this Mac user can open: no network port, nothing a web page can reach.
- Saves go through the system's safe save, so a failed save leaves the old file whole.
- Export timing is exact, files are written aside and moved into place, and the ffmpeg handling avoids the usual traps.
- No TODO or FIXME left behind; the few forced operations in the code are all harmless.

## A. Can lose or destroy work

**A1. An AI app's export can replace a whole folder.** Confirmed (the reviewer also reproduced the file operation on a scratch folder). **Status: Fixed in v0.2.56.**
If an AI app calls export with a path that is an existing folder, such as a Renders folder or a .twine project, the folder and everything in it is deleted outright (not moved to the Bin) and one file takes its name. An existing file of any kind is overwritten silently too.
Where: Packages/MotionKit/Sources/MotionAgent/TwineAgent.swift:802, Twine/Agent/AppAgentHost.swift:186, Packages/MotionKit/Sources/MotionExport/Exporter.swift:126.

**A2. Clicking into a number field and out again can change the value.** Confirmed. **Status: Fixed in v0.2.56.**
On losing focus a field compares the number in its text with the exact stored value, not with what it was showing. Whenever the shown number is rounded, the two differ and the rounded one is written back. With one layer this nudges it (X 100.25 becomes 100.2) and adds an undo step. With several things selected it is much worse, because the field shows the first one's value and writes it to all:
- several timeline bars with different starts: click Start, click away, and every bar gets the first bar's start, so a stagger collapses;
- two layers at 30% and 55% opacity: both become 55%;
- several texts of different colours: all take the first one's colour.
Where: Twine/Components/Controls.swift:464-477 and 567-580, Twine/Components/ColorControls.swift:103-113; the several-things cases at Twine/Editor/ActionInspector.swift:406-419, Twine/Editor/LayerInspector.swift:469, Twine/Editor/TextInspector.swift:296-307.

**A3. A drag's undo step can be left open, or scrambled.** Store side confirmed; one trigger plausible. **Status: Fixed in v0.2.56 (tried in the test copy for the field; the held-drag cases not exercised with a real mouse).**
The store's "continuous change" (how a drag becomes one undo step) trusts every caller to open and close it and to keep everything else out in between. Three things break that:
- *A command that lands mid-drag.* Delete or Command-Z pressed while holding a layer, an import finishing, or an AI edit arriving. Afterwards Undo steps go out of order, one of them landing on a half-dragged state that never existed; Escape throws the interleaved change away while its undo step stays. Confirmed.
- *A drag that never ends.* A middle click during a timeline bar drag, or Return while dragging a text layer, leaves the change open until some later drag ends. Confirmed.
- *A number-field drag whose field disappears.* Dragging Tilt, Skew, Bend or Z to exactly 0 removes the field under the pointer; so does Escape mid-drag. The drag stops dead (confirmed). If the mouse-up then never reaches the removed field (plausible, the code's own comments suggest so), every later edit is applied without an undo step and without marking the document edited, so nothing autosaves; the next drag that ends rolls it all into one step, and one that is cancelled throws it all away.
Where: Packages/MotionKit/Sources/MotionEditing/ProjectStore.swift:53-131 and 180-193, Twine/Components/Controls.swift:1071-1137, Twine/Timeline/TimelineTracksView.swift:714-718, Twine/Canvas/CanvasNSView.swift:956 and 1461-1522, Twine/Agent/AppAgentHost.swift:55-59.
One fix covers all three: have the store itself close or refuse an open change in perform, undo and begin, and end the scrub when its view leaves the window.

**A4. An open colour picker can put an old copy of the layer back.** Confirmed by reading. **Status: Fixed in v0.2.58.**
A fill, stroke or shadow picker keeps the whole layer as it was when the picker opened. Nudge the layer with the arrow keys (or have an AI app move it) while the picker is up, then drag in the picker again: the layer jumps back. On a frame, anything added inside it meanwhile is removed, with its actions. The text fill section was already fixed to read the layer afresh; the older sections were not.
Where: Twine/Editor/LayerInspector.swift:605, 621-626, 774-780, 1354, 1458-1472; Twine/Editor/TextInspector.swift:344.

**A5. File > Duplicate makes a project that lives nowhere.** Plausible (Twine's side confirmed, the system's side not run). **Status: Fixed in v0.2.58: File > Duplicate is Twine's own, a real project beside the original.**
The menu item is the system's stock Duplicate. Its copy has no file, so pictures and video show grey, it is not in the projects folder, Home never lists it, and it takes over the one window. Home's own Duplicate is fine.
Where: Twine/App/MainMenu.swift:68.

**A6. The one-second save hides its failures.** Confirmed. **Status: Fixed in v0.2.58: a note says when saving fails.**
If saving starts failing (disk full, drive gone, a value that cannot be written), every save fails without a word until the project is closed.
Where: Twine/Document/ProjectDocument.swift:236.

**A7. A NaN from an SVG makes a project impossible to save.** Confirmed. **Status: Fixed in v0.2.58.**
Gradient positions, stop offsets and one blur value in the SVG reader skip the check every other number gets. "nan" lands in the model, and every save fails from then on until the layer is deleted. Together with A6 the failure is silent.
Where: Packages/MotionKit/Sources/MotionImport/SVGImport.swift:648-649, 671-675, 355-357.

## B. Crashes

**B1. A template frame of zero width or height.** Confirmed. **Status: Fixed in v0.2.57.**
A Resize action on a template frame with From or To of 0 (a "grow in from nothing") stops the app as soon as the field commits, and again on every reopen. Nine template kinds are affected. A frame one pixel thin does not crash but makes tens of thousands of cards a frame.
Where: Packages/MotionKit/Sources/MotionEvaluation/TemplateRecipes.swift:414 and 459, FlatTemplateRecipes.swift:205, 349, 495, 520.

**B2. The export range outlives a shorter scene.** Confirmed. **Status: Fixed in v0.2.57.**
Set a range of 3 to 5 seconds, shorten the scene to 2 seconds, reopen Export and type in To: crash. Left untouched it exports a single frame with no message.
Where: Twine/Editor/ExportPanel.swift:168-175, Twine/Editor/ExportSession.swift:23.

**B3. Very large or very small numbers typed into fields.** Confirmed. **Status: Fixed in v0.2.57.**
Typing a twenty-digit number (or 1e19) into a whole-number field such as a Move's To X, Resize, Z-Index, or Start in frames crashes when the field redraws. A custom frame rate of 0.0003 crashes too. Inspector fields are also the one way in that skips the limits files and the AI tools pass through.
Where: Twine/Components/Controls.swift:428-430 and 550-552, Twine/Editor/InspectorPanel.swift:142-145 and 218-226.

**B4. Two AI tool arguments.** Confirmed. **Status: Fixed in v0.2.57.**
Export with fps of 0 (a likely way for an AI to mean "default") or a negative or huge fps; and any text argument given as an enormous number.
Where: Packages/MotionKit/Sources/MotionAgent/TwineAgent.swift:811, AgentArguments.swift:22, Packages/MotionKit/Sources/MotionModel/Time.swift:13.

**B5. Files from elsewhere.** All need a hand-made, damaged or hostile file. **Status: Fixed in v0.2.66 (the sound-as-mask crash went with v0.2.60's mask work).**
- An SVG can walk past the two guards in front of the XML reader: the entity check stops at the first ">" inside a quoted value (a few hundred bytes can grow into gigabytes), and the nesting counter can be driven negative from inside a DOCTYPE (a file nested 100,000 deep then crashes the reader). SVGImport.swift:126-136 and 142-195. Check confirmed; the blow-up rests on the code's own notes.
- Two actions sharing an id crash on dragging the bar (TimelineTracksView.swift:763). Duplicate ids are neither refused nor repaired on open; two layers sharing one means edits to the second land on the first.
- A sound layer marked as a mask crashes every evaluation, so the project cannot open (Evaluate.swift:397-404).
- A .twine whose document.json is a link or a folder crashes the open (ProjectDocument.swift:41-42).
- A layer named "Rectangle 9223372036854775807" crashes the next new rectangle (LayerFactory.swift:110-116).
- A clip path of 50,000 shapes used by 50,000 elements is read again for each, outside every budget (SVGImport.swift:780-798).
- A file with duration 0 opens into a state where most composition edits are refused (FileSafety.swift:139).

## C. Wrong results

**C1. Sound in a hidden frame or group still plays.** Confirmed. Hide a frame holding a video with sound: the picture goes, the sound stays, in preview and export. Packages/MotionKit/Sources/MotionEvaluation/AudioClips.swift:61. **Status: Fixed in v0.2.59.**

**C2. Lottie: an erasing line exports as a full line.** Confirmed. A stroke that is whole at the first exported frame and trimmed later (100% to 0%) comes out untrimmed, and the leaves-out notice says nothing. Packages/MotionKit/Sources/MotionExport/Lottie/LottieWriter.swift:440-441. **Status: Fixed in v0.2.59.**

**C3. A click that wobbles moves the layer.** Confirmed. Path points and gradients have a few points of dead zone; a plain move, a resize and a drawn shape act on the first pixel. A click to select with one point of wobble shifts the layer and adds a "Move Layer" step; with snapping on, it can jump onto a guide. A wobbly click with a shape tool makes a one-pixel shape; a wobbly Option-click leaves a duplicate on top of the original. Twine/Canvas/CanvasNSView.swift:842-878 and 961-992. **Status: Fixed in v0.2.59.**

**C4. Copy and paste out of a frame lands in the wrong place.** Confirmed. A layer copied from inside a frame or group pastes at the top level with its inside-the-frame position, so it appears somewhere else; Duplicate does this correctly. Pasted into another project, pictures and videos show grey with no notice. Twine/Editor/EditorController.swift:1561-1572 and 1627-1638. **Status: Fixed in v0.2.59 (pasting pictures into another project is built but was not exercised).**

**C5. Videos in a still template freeze.** Confirmed. A template with a video slot and no template bar plays its videos without the cache, but on the canvas they freeze at the last edit and in an export at the first frame. Packages/MotionKit/Sources/MotionEvaluation/Evaluate.swift:252-257 and 311-318. **Status: Fixed in v0.2.59.**

**C6. Some videos restart their reader on every draw and can show the wrong frame.** Logic confirmed, not run. Files whose first frame starts after 0 (some screen recorders) or with gaps longer than half a second between frames. Packages/MotionKit/Sources/MotionRendering/Media.swift:144-199. **Status: Guarded in v0.2.64. Not reproduced: files that could be generated already read correctly with the old code.**

**C7. The playhead can rest outside the scene.** Confirmed. Park at 8 seconds, shorten the scene to 5: the canvas shows a moment that is not in the scene, Export Current Frame exports it, Add Action puts a bar past the end. EditorController.swift:1227-1231. **Status: Fixed in v0.2.64.**

**C8. A waveform never comes back after delete and undo.** Confirmed. Twine/Timeline/Waveforms.swift:19-35. **Status: Fixed in v0.2.64.**

**C9. After Return, a field shows what was typed, not what was stored.** Confirmed. Start typed 0.52 at 30 fps is stored as 0.5333 and still reads 0.52; Glass Depth typed 5000 is stored as 100 and reads 5000. Controls.swift:468-473. **Status: Fixed in v0.2.64.**

**C10. Smaller ones.** All confirmed unless marked. **Status: Most fixed in v0.2.64; each line below says which.**
- Turning a layer inside a mirrored group goes the wrong way (CanvasNSView.swift:921-928). **Status: Fixed in v0.2.64.**
- Go to Start within a second of adding an action is undone by the gliding playhead (EditorController.swift:301-340). **Status: Fixed in v0.2.64.**
- The AI undo tool also undoes the person's own steps (AppAgentHost.swift:71-85); the AI export shows its done notice even when it failed, and cannot be cancelled. **Status: The export's done notice fixed in v0.2.64. The undo tool's reach and cancelling an AI export are left as they were: a design question.**
- Shift-click in the layers panel leaves actions of deselected layers selected (LayersPanel.swift:84-86). **Status: Fixed in v0.2.64.**
- The eyedropper sets full opacity where the hex field keeps the fill's (ColorPicker.swift:302-305). **Status: Fixed in v0.2.64.**
- A GIF of an odd-sized scene is stretched by one pixel (ExportSettings.swift:187-194); possibly deliberate. **Status: Left as it is: it looks deliberate.**
- Lottie drops emoji and unreadable pictures without saying so. **Status: Emoji are named since v0.2.64. An unreadable picture is still dropped without a word.**
- A page curl is not redrawn when the layer is resized while paused (CoreAnimationRenderer.swift:614-624). **Status: Fixed in v0.2.64.**
- Installing a font while Twine is open does not redraw text already on screen. **Status: Open. Reopening the project redraws.**
- The pixel scale does not reach clip masks, shadows and the glass mask, so their edges may be soft at 800% or in a 2x export (plausible, needs a look on screen; CoreAnimationRenderer.swift:518-525). **Status: Open: needs a look on screen.**
- Converting pre-October masks drops one when a mask was itself masked (MaskConversion.swift:30-47). **Status: Open: no such files are known.**
- A range that starts after the last sound ends, with Audio on, may fail the export or write an empty track (plausible; AudioMixdown.swift:50-51). **Status: Open: not looked into.**
- Cut with the timeline focused and no action selected copies the layers and deletes nothing. **Status: Fixed in v0.2.64.**
- Return in a rename field may leave the keyboard nowhere until a click (plausible). **Status: Fixed in v0.2.64.**
- Laid-out text lines are shared between the canvas and a running export, which Core Text advises against: a rare crash is possible (plausible; TextLayout.swift:136-139). **Status: Open: a risky change for a crash nobody has seen.**

## D. Performance that has drifted from the rules

None of these was measured; each is the kind of per-frame or per-layer scan CLAUDE.md warns about, on a path the benchmarks do not cover.

**D1. One mask anywhere makes every frame do whole-project work.** A copy of all layers and four dictionaries of them, every frame. Figma and SVG imports nearly always have masks, so the 1.8 ms figure for large projects likely does not hold there. Worth running the large benchmark with one mask added. Evaluate.swift:327-355, CoreAnimationRenderer.swift:302-322. **Status: Fixed in v0.2.60: 6.0 ms a frame down to 1.5 in the large scene.**

**D2. The timeline rebuilds every row on every playhead tick**, when a time change needs only a redraw; and the sound preview copies all layers and regroups all actions each tick just to compare with the last. TimelineTracksView.swift:31-39 and 122-139, Twine/Editor/AudioPreview.swift:65-75. **Status: Fixed in v0.2.60.**

**D3. A second, uncached evaluation on every redraw** while a Scale, Resize, Rotate or Path action is selected, which is the state right after adding one. CanvasNSView.swift:460-466, CanvasPathEditing.swift:174, CanvasGradient.swift:99. **Status: Fixed in v0.2.60: playback with a Scale action selected 45 to 60 frames a second.**

**D4. Text pictures have no real size cap and are all redrawn on every pinch frame.** At 800% on a Retina screen a headline is about 100 MB, every text gets one whether on screen or not, and every zoom step redraws them all. Glass was given power-of-two rounding for exactly this; text was not. CoreAnimationRenderer.swift:332-335 and 518-525. **Status: Partly fixed in v0.2.60: texts keep their pictures during a zoom and a picture's longer side is capped. Texts off screen are still drawn at full zoom.**

**D5. Bulk edits scan per item.** Split into Layers on a sequence template with many loops can make over 100,000 actions, each checked against all the others (tens of seconds frozen, estimated). Grouping or moving thousands of layers at once walks the tree per layer. EditorCommand.swift:127-139 and 162-176, Templates.swift:261-300, Arrangement.swift:118-131. **Status: Fixed in v0.2.65: 20,000 actions added in 5 ms (435 before), 2,000 layers moved in 13 ms (455). Split into Layers refuses too many loops.**

**D6. Home reads and decodes every project in full, on the main thread, at every launch**, only to learn each one's shape. Twine/Home/Library.swift:93-95. **Status: Fixed in v0.2.65: a project with a thumbnail is no longer read. Not timed.**

**D7. Smaller.** Selection colours gathers every colour under the selection on each step of a canvas drag (SelectionColorsSection.swift:24); the layers panel walks ancestors once per selected layer (LayersPanel.swift:57-59); no memory pool is drained between export frames (plausible; OffscreenRenderer.swift:133-170). **Status: Partly fixed in v0.2.65: the layers panel and the export memory pool. Selection colours left as it was.**

**D8. Imported media never leaves a project.** Import an 800 MB video, delete the layer, save: the package is still 800 MB, and Duplicate copies it along. Nothing in the app can shrink a project. **Status: Fixed in v0.2.65: unused files are let go when a project is opened.**

## E. The project's own rules

- **"Views never write literals"** holds for colour, type and radius, but not for spacing. Views carry about 180 literal spacings (120 of them 8), 44 paddings, 25 line widths, 19 opacity strengths and 15 fixed sizes; Theme has no spacing tokens to use instead. One colour literal: white at Twine/Timeline/TimelineTracksView.swift:491, beside a corner radius of 6. **Status: Open.**
- **"Make clickable controls real buttons"**: ten tap gestures remain. The ones that matter are layer rows (select and rename, LayersPanel.swift:250) and Home's project cards (HomeView.swift:378); the rest are backdrops that close a card. **Status: Open: layer rows and Home's cards are still tap gestures.**
- **No accessibility labels anywhere.** Icon-only buttons have tooltips only, so VoiceOver reads "button", and the test kit has only positions to go by. **Status: Open.**
- **Shortcuts card**: no key on it is wrong. It leaves out conditions (Space pans in Design but plays in Animate; align keys, Paste Style and Return-to-edit-points are Design only) and some keys that work (Up and Down nudge, arrows and Shift in number fields, pinch zoom, Shift and Command click in the layers panel). While the card is up, keys still act on the canvas behind it: Delete deletes the selection. **Status: Partly: Zoom to Selection and Close Project were added (v0.2.61, v0.2.62), and keys no longer reach the canvas behind an open menu (v0.2.63). The conditions and the other missing keys are still not on the card.**
- **CLAUDE.md's layers table** lists fewer system frameworks than the modules now import (Core Image, Accelerate, IOSurface and others in rendering, for instance). The direction of every module dependency is right; only the table is behind. **Status: Open.**

## F. Housekeeping

- .gitignore does not cover .claude/ (1.8 GB of worktree copies), Exports/ or Website/. With several sessions committing here, one "add everything" would commit them. **Status: Fixed in v0.2.69.**
- VersionHistory.pushes is 255; the branch has 256 commits. **Status: Fixed in v0.2.69: the counter matches the commit count again.**
- Built straight from Xcode, the app says version 1: only make-app.sh passes the real number. **Status: Fixed in v0.2.69: the build script keeps the project file at the same number.**
- Test kit scripts: make-test-app.sh hides a failed build and packages the previous app as the test copy; profile.sh kills TwineTest at once without asking it to quit and save (the 28 September situation); run.sh with an empty name moves the whole output folder to the Bin. **Status: Fixed in v0.2.69: a failed build stops the test copy being made, the profiler asks the test copy to quit, and a run needs a name.**
- Home treats any ordinary folder in the projects folder as its own and bins it in one click with no count of what is inside (only a risk if the projects folder is set to something like Documents). **Status: Fixed in v0.2.69: a folder holding anything else asks first.**
- The AI tools accept any path: they can read any picture, video, sound or SVG this Mac user can, and export anywhere. By the written decision, but worth knowing alongside A1. **Status: Export can no longer replace a folder or a file of another kind (v0.2.56). Reading and writing anywhere this Mac user can is by the written decision.**
- The README's Status section stops before templates, Glass, Lottie and the AI connection. **Status: Fixed in v0.2.69.**
- build/ is 3.3 GB (ignored by git; safe to clear). **Status: Nothing to fix.**

## Tests that are missing

The app itself has no automated tests; everything is in the packages. Gaps that match findings above: commands arriving during a drag; duplicate ids; a saved file per old format opened end to end; template recipes at odd frame sizes; video seeking (going back, gaps, late first frame); the evaluation cache with masks, templates and videos; cancelling a GIF, WebM, Lottie or any export with sound; an unwritable folder or full disk; the SVG cases in B5 and A7; the AI export's arguments.

## Suggested order

1. A1, A2, A3: the three that can cost work in ordinary use. A1 and A2 are small, local fixes; A3 is one change to the store plus one line in the scrub view.
2. B1 to B4: four crashes reachable from the app's own fields and tools, each a clamp or a guard.
3. A4 to A7, then C1 to C5.
4. D1 to D4, measured before and after.
5. B5 and the rest as they come up.
